# Hay Day → 햇살 바구니: 독립 디자인·수학 기준

**초기 판단:** 농장 넓이를 직접 늘려 주문량을 맞추고 수확하는 구조는 수학과 행동을 연결한다. 최종 아트·조작·게시 점수는 실제 게임 검수 전까지 미정이다.

[Supercell 공식 소개](https://supercell.com/en/games/hayday/)는 평온한 농장과 죽지 않는 작물을 강조한다. [개발자 공식 스토어 설명](https://play.google.com/store/apps/details?id=com.supercell.hayday)은 재배→수확→가공/주문→판매→농장 확장을 연결한다. 이 작품에는 짧은 성장·직접 수확·수레 운송·실제 농장 장식이라는 행동의 연결을 적용한다. 기다림과 온라인 경제를 그대로 옮기지 않는다.

## 직접 본 이미지에서 도출한 설계

[공식 플레이 이미지](https://supercell.com/images/32e8c9bae8508f7e03d245e466a206ff/Hay_Day_iPhone_image_V3.png)를 직접 열었다. 아래는 화면 관찰을 바탕으로 한 독립 설계 해석이다.

- **낮은 3/4 구도:** 건물 앞면·입구와 지붕, 밭 작물이 동시에 보인다. 햇살 바구니도 높은 조감으로 작물 꼭대기만 보이는 구도를 피한다.
- **행동을 연결하는 길:** 흙길이 판매대·주문판·차량·생산 구역을 잇는다. 중앙 밭에서 나온 상자가 수레와 가게로 이동하는 경로를 화면에서 보여 준다.
- **큰 형태와 재료 분리:** 굵은 목재 테두리, 깊은 입구, 둥근 지붕, 겹친 잎이 집·과수·작물의 역할을 나눈다. 성벽과 균일한 상자 대열을 농장색으로 칠한 화면을 피한다.
- **성장 상태의 변화:** 갈색 흙·초록 잎·고채도 열매를 분리하고 모양도 변하게 한다. 열린 흙길과 유기적인 풀 가장자리는 정확한 직사각형 밭을 둘러싸는 환경으로 사용한다.

[로컬 참조](../../logs/manual-20260907-sunbasket-farm/validation/reference/hayday-official-iphone.png). 스토어의 세 이미지는 실제 플레이에 캐릭터·설명·화살표를 합성한 홍보 이미지 또는 키아트로 구분했다. 홍보 그림을 실제 플레이 품질 증거로 쓰지 않는다. 참조 이미지는 분석 전용이며 제작 에셋으로 사용하지 않는다.

## 수학 구현에서 지킬 연결

1. “이 밭은 1m²마다 1상자” 가정을 계획 중 표시한다. 가로6m·주문42상자이면 필요한 넓이42m², 세로7m다. `가로×현재 세로`의 넓이/생산량 자동 표시는 제출 전 숨긴다.
2. 가로·정답 세로3..12와 넓이12..144를 함께 지키려면 `(3,3)=9`를 제외한다. 전체 조합은99쌍이며 튜토리얼과 일반 풀의 중복 정책은 구현에서 확인한다.
3. 정답·첫 시도 성적은 **심기**에서 확정한다. 수확 개수는 이미 맞힌 밭의 작업 진도이며 수학 정답률로 합산하지 않는다. 한 셀의 여러 잎/열매는 한 상자를 뜻하고, 동일 셀을 다시 쓸어도 보상이 늘지 않아야 한다.
4. 오답 뒤 같은 밭을 손잡이·±1m·키보드로 바로 수정한다. 수확 셀은 모두 실제로 보이며 손으로 닿아야 한다. SPACE 줄 수확과 포커스 상실 처리를 별도 확인한다.
5. 초기2m 제출, 고정6m, 끝12m, 무작위1..12 정책의 첫 시도율을 **각 정책의 실제 출제 분포 기준**과 비교한다. 무작위1..12의 우연값은1/12이며 고정값의 우연값은 별도다. 튜토리얼은 제외한다. 작은 UI 표본이나 완주 실패를 학습 효과로 해석하지 않는다.

독립 검산은 생산 함수와 별도 정수 오라클로 풀·생성기·판정을 대조한다. 최종 UI 정상9주문, 일반1오답 후9주문,3오답 종료·재시작, 직접 수확·키보드·저장은 호스트 증거와 겹치지 않게 확인한다. 상용 아트 동급이나 아동 이해·재방문을 추정하지 않는다.
