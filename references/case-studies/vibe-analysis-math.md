## 매스몬 시리즈 (에듀잇티, 3학년 2학기, 공용 엔진 + 단원별 스킨)

7개 게임(box-run, rocket-charge, jump-islands, fusion, divide-farm, elevator, star-pickup)이 동일한 "레슨 엔진" 위에서 `LESSON_CONFIG` JSON(제목/튜토리얼 카드/보상 가중치/결과 임계값/QA 뷰포트)만 갈아끼우는 구조. 시드 PRNG 기반 절차적 문제 생성, 힌트→재시도→정답공개의 처벌 없는 오답 루프, 슬롯머신형 가중치 랜덤 보상 이벤트, `misconceptionId` 태깅 오답을 공통으로 공유한다.

### 1. 매스몬 상자런 (box-run)
- **단원**: 3-2-1단원 1차시, 받아올림 없는 (세 자리 수)×(한 자리 수)
- **핵심 루프**: 10문제 풀며 정답마다 상자 획득 → 상자를 열어 슬롯머신형 보상(±점수, 배율) → 누적 점수(BigInt, 억/조 단위)로 10단계 매스몬 컬렉션.
- **잘 만든 이유**: 정답→가챠 오픈이라는 2단 보상 구조. BigInt로 억/조 단위 숫자를 실제로 찍어 임팩트를 줌. 10단계 몬스터 컬렉션으로 장기 재방문 동기.
- **문제 생성**: 완전 절차적(`buildQuestionBank`, 받아올림 없는 조합만 필터). 오답은 `buildChoices`에서 자릿값 슬립(일/십/백의 자리만 틀린 값)을 우선 생성 — 순수 랜덤이 아니라 정조준 오답.
- **관용도/세션**: 오답 2회까지, 2회째는 정답 자동표시 + 나쁜 보상만 있는 "깨진 상자" 오픈. 생명/타이머 없음. 10문제, 2~5분.
- **비주얼**: 판타지 캐릭터(아기 드래곤, 여우) AI 생성 일러스트, 화려한 첫 화면.
- **버그**: 독립 URL 직접 접속 시 시작 버튼 완전히 죽음(`../_shared/scoreboard/...` 404 → try/catch 없이 전체 스크립트 중단). 소스 분석으로 대체.
- **훔칠 것**: (1) 자릿값 슬립 오답 생성 로직. (2) 정답 후 가챠 오픈 2단 보상 + BigInt 점수 임팩트. (반면교사) 공유 스크립트 로드 실패는 반드시 try/catch.

### 2. 매스몬 로켓발사 대작전 (rocket-charge)
- **단원**: 3-2-1단원 2차시, 받아올림 있는 (세 자리 수)×(한 자리 수)
- **핵심 루프**: 세로셈(필산)을 일→십→백의 자리 3단계로 쪼개 각 단계 객관식으로 풀게 하고, 정답마다 세로셈판에 애니메이션으로 숫자가 채워짐. 10문제 무실수 정도에 따라 로켓 연료가 차서 도달 행성이 갈림.
- **잘 만든 이유**: 최종답이 아니라 **표준 필산 알고리즘 자체를 스캐폴딩**. 튜토리얼이 "무엇을 얻어요?" 카드형 5단계 + 마스코트 응원 연출. 완벽클리어(3스텝 무실수)=perfect 이벤트, 실수 있으면 leak 이벤트로 서사 분기.
- **문제 생성**: `buildProblems()` — 받아올림이 실제 발생하는 조합만, 곱이 표시 자릿수에 맞는 범위만 필터링해 차시 범위를 벗어나지 않게 설계. 스텝별 오답(`buildStepOptions`)은 정답±1/±2/±10 — "받아올림 깜빡함", "한 자리 밀림" 등 전형적 실수 정조준.
- **관용도/세션**: 스텝당 1회 재시도(힌트) 후 자동 정답공개+설명. 10문제×3스텝=약 30회 응답, 3~6분.
- **훔칠 것**: (1) 필산 알고리즘을 스텝별로 쪼개 세로셈판에 실시간 반영하는 패턴. (2) 스텝별 오답을 "그 자리에서만 나올 수 있는 실수"로 한정하는 규칙.

### 3. 매스몬 10배 점프섬 (jump-islands)
- **단원**: 3-2-1단원 3차시, (몇십)×(몇십), (몇십몇)×(몇십)
- **핵심 루프**: "0을 가리고 곱한 뒤 다시 붙인다"를 2스텝 퀴즈로(①0 가린 소곱 풀기 ②0 붙이는 방법 고르기). 정답마다 가중치 RNG 바람 이벤트로 점프 거리 결정, 지도 위 섬 이동.
- **잘 만든 이유**: 이 차시의 핵심 트릭을 **튜토리얼 카드 3장과 게임 인터랙션 스텝을 1:1로 일치**시킴. 결과가 정답수(`minCorrect`)와 누적파워(`minPower`) 둘 다 충족해야 상위 섬 도달 — 실력+운의 다중조건.
- **문제 생성**: `chooseProblems()`에서 난이도 큐레이션 — 같은 최종답 중복 금지, 같은 인수쌍 재사용 2회 이하, "너무 쉬운 문제"는 라운드당 1개만. 유형 5:5 고정 배분.
- **훔칠 것**: (1) 최종답 중복 방지 + 인수쌍 재사용 상한 + 쉬운문제 개수 제한이라는 난이도 큐레이션 로직 통째로. (2) "개념 설명 카피 = 게임 스텝 순서" 매핑 원칙.

### 4. 매스몬 로봇 합체 (fusion)
- **단원**: 3-2-1단원 4차시, (몇)×(몇십몇), (몇십몇)×(몇십몇)
- **핵심 루프**: 곱셈을 일의자리곱→십의자리곱(0붙이기)→합산 3단계로 쪼개 풀며 로봇 부품을 조립, 최종 로봇 완성.
- **잘 만든 이유**: "어떻게 풀어요?"(예시 전체 시연) + "무엇을 얻어요?"(보상구조 설명) 2단 온보딩. 상단 6단계 로봇 실루엣 진행 레일 상시 노출. 캐릭터가 진행상태를 계속 서사화.
- **문제 생성**: 시드 PRNG 완전 절차적. 오답이 오개념 기반(top×(곱수±1) 자리헷갈림, 0 안붙인 값, 부분곱을 잘못 더한 값 등) — misconception 모델링 최상급.
- **버그**: box-run과 동일한 `_shared/` 404 문제로 **독립 URL 접속 시 시작버튼 완전히 죽음**. 스텁 주입으로 우회 확인. 반면 divide-farm/elevator는 같은 모듈을 self-contained IIFE + 옵셔널체이닝으로 방어해 정상 동작 — **같은 시리즈 안에서도 배포 안정성 편차가 존재한다는 것 자체가 QA 시사점**.
- **훔칠 것**: (1) 오개념 기반 오답 생성(자리밀림/인접수혼동/부분합 오류)을 표준 규칙화. (2) 외부 공유 모듈 self-contained화 + QA 단계에서 404 스캔 자동화.

### 5. 매스몬 나누기 농장 (divide-farm)
- **단원**: 3-2-2단원, 내림 없는 두 자리 수 나눗셈
- **핵심 루프**: 당근을 "묶음(십의자리)"과 "낱개(일의자리)"로 나눠 두 바구니에 등분 배분 → 실제 문제에서 "몇 묶음"을 선택.
- **잘 만든 이유**: 40÷4=10, 8÷4=2 두 단계를 당근 이모지+숫자 배지로 시각화 후 합산 — 자릿값 분해 원리를 그림으로 먼저 체험. 바구니 배분 은유가 등분제 개념과 정확히 대응.
- **문제 생성**: `buildPool()` — 10~99 피제수×제수(2~5) 전수조합 중 "내림 없음" 조건 만족하는 것만 필터해 풀 구성. `makeShareOptionSet()`이 오답마다 `misconceptionId`+**왜 틀렸는지 설명하는 피드백 문구**("3개가 남아요")까지 자동 생성.
- **훔칠 것**: (1) 오답=오답값+진단설명 문구를 한 쌍으로 자동 생성. (2) "전수조합 생성 후 단원 제약으로 필터링"하는 풀 구성 방식 — 사후검증이 아니라 원천 차단.

### 6. 매스몬 엘리베이터 (elevator)
- **단원**: 3-2-2단원, 내림 있는 두 자리 수 나눗셈
- **핵심 루프**: 세로 나눗셈(장제법)을 "70÷2 먼저→10과6 합침→16÷2=8" 3단계로 시각화 후 몫/나머지를 4지선다로 선택. 엘리베이터가 층을 오르내리는 진행 은유.
- **잘 만든 이유**: 필산 형식(세로 나눗셈 박스)을 그대로 재현하며 검산까지 튜토리얼에서 보여줌. 진행바가 "지금/다음 구역명" 경로 표시로 기대감 부여.
- **문제 생성**: 절차적, 나머지 발생 조합. 오답이 몫 과대추정/과소추정/나머지 계산 누락 등 장제법 특유의 실수를 정확히 겨냥.
- **훔칠 것**: (1) 장제법 세로형 UI+부분검산 노출을 튜토리얼 표준 컴포넌트로. (2) 진행 표시를 단원 테마와 연결된 공간 은유(엘리베이터/로봇조립/농장)로 만드는 규칙화.

### 7. 매스몬 별 줍기 (star-pickup)
- **단원**: 3-2-2단원, 나머지가 있는 나눗셈
- **핵심 루프**: 별 무더기를 보고 "몇 묶음(몫)"→"남은 별(나머지)" 2단계 퀴즈. 정답 수에 따라 "유니콘자리" 게이지가 채워지며 6단계 티어 결과 이미지 언락.
- **잘 만든 이유**: **정답 시엔 마이너스 이벤트가 절대 안 나오는 `correctProtection` 안전장치** — 틀려도 손해볼 수 있지만 맞히면 절대 손해 안 봄. 별을 실제 6개씩 묶어 시각화 + 최종 검산식(`6×7+5=47`)까지 노출해 "몫×나누는수+나머지=나눠지는수" 개념을 매 문제 각인.
- **문제 생성**: 시드 기반 mulberry32 RNG, URL `?seed=`로 QA 재현 가능. 오답에 `misconceptionId`(`DIV3_QUOTIENT_TOO_HIGH` 등)와 전용 피드백 문장 페어링.
- **훔칠 것**: (1) 오답마다 `misconceptionId`+전용 피드백을 페어로 설계하는 표준. (2) 랜덤 보상이라도 "정답이면 절대 손해 없음"을 코드로 보장하는 규칙.

## 독립 게임 4종

### 8. Quiz Survivor: 분수의 나눗셈 (quiz-math-6-1-1)
- **단원**: 6학년 1학기 1단원, 분수의 나눗셈
- **핵심 루프**: 뱀서라이크(Vampire Survivors류) 액션 — 조이스틱 이동+자동공격으로 몬스터 처치, XP로 레벨업 시 퀴즈를 맞혀 무기 강화, 생존 타이머 챌린지.
- **잘 만든 이유**: 난이도(쉬움/보통/어려움)×모드(모험/10분 챌린지) 자율 선택, 하드모드는 오답에 실제 페널티 부여로 **관용도 자체를 난이도 옵션화**. HUD가 HP바/XP바/실시간 랭킹 추월 알림까지 완비된 진짜 게임. 무기가 "연필"로 스킨된 학습 소재 오브젝트.
- **문제 생성**: 완전 하드코딩 300문항(calc 215/word 45/concept 40, 난이도 1~3)을 별도 JS 청크에 JSON으로 사전 제작. 워드프라블럼은 생태/환경 소재로 문맥만 바꿔가며 같은 수식 패턴 반복. 오답은 분자분모 뒤바꿈(역수), 분모 off-by-one.
- **관용도/세션**: HP 소진=게임오버, 조작 안 하면 30초 내 사망. 최대 10분, 결과 Firebase 랭킹 등록.
- **비주얼**: 픽셀아트 레트로 RPG, 어두운 숲+파티클 VFX. 몰입도는 11개 중 최상급.
- **훔칠 것**: (1) 난이도별 관용도 차등화(쉬움=관용, 어려움=페널티)를 선택 UI로 노출. (2) 실시간 생성 대신 "빌드타임 대량 문항×소재 치환" 정적 뱅크 방식 — QA 안정성 높고 생성 실패 리스크 없음.

### 9. 네모시티 도형 구조대 (quadrilateral-rescue)
- **단원**: 추정 4학년, 수직/평행/사각형 (직각게이트→레일역→사다리꼴성/보석광산→사각형탐정→별문광장 5스테이지)
- **핵심 루프**: 월드맵에서 스테이지 선택 → 스토리 인트로 → 조건에 맞는 직선 멀티선택 + 드래그형 삼각자로 실측 → 별 3종 보상.
- **잘 만든 이유**: 11개 중 **비주얼 완성도 압도적**(테마파크 IP급 아트, 경찰고양이·로봇삼각자 캐릭터). Candy Crush류 월드맵으로 커리큘럼 전체를 미리 보여줌. 드래그 삼각자로 "직각에 대보기" 조작적 검증(manipulative). 선을 클릭하면 실측 각도가 배지로 즉시 표시. 별 3종(발견/정답/설명)으로 "왜 맞았는지"까지 평가.
- **문제 생성**: 하드코딩 미션 데이터(`mission-config.json`, 좌표 기반)지만 정답 판정은 실제 벡터 연산(허용오차 4도)으로 계산 — 정답이 박힌 게 아니라 기하학적으로 검증됨.
- **관용도/세션**: 미션당 120초, 힌트 상시, 무제한 재시도. 5스테이지 완주 15~20분.
- **훔칠 것**: (1) 좌표+벡터연산 기반 실측 판정(허용오차) 미니게임 템플릿 — 도형 단원(수직/평행/각도/합동)에 재사용 가능한 표준 블록으로. (2) 정답 선택 후 "왜 그런가요?" 개념설명 문항을 별도 배점으로 강제 포함.

### 10. 합리적 소비 대작전 (smart-shopping-mission)
- **단원**: 실과/사회 "합리적 소비" (5~6학년), 수학적으로는 예산 뺄셈+가격비교
- **핵심 루프**: 5만원 예산으로 미션 조건(필요한 것 우선, 가격비교, 생산지 확인 등) 지키며 시장 4개 장소를 돌아 상품 선택.
- **잘 만든 이유**: **미션 조건 5개를 전부 체크해야만 시작버튼이 활성화**되는 강제 체크리스트 온보딩. isometric CG 배경(이모지 아님)으로 첫인상 강함. 예산 초과 시 하드락 대신 "~초과했어요, 재검토해보세요" 소프트 피드백. `budget_keeper`, `compare_king` 등 행동패턴 기반 배지 5종.
- **문제 생성**: 완전 하드코딩(상품 9개 내외, 가격/생산지 고정 배열). 오답 개념 자체 없음(객관식이 아니라 시뮬레이션형).
- **관용도/세션**: 라이프/타이머 없음, 재조정 가능. 10~15분 이상 장문 세션.
- **훔칠 것**: (1) "학습목표 체크리스트 전부 확인해야 시작 가능" 게이팅 온보딩. (2) "~을 X 초과했어요, ~해보세요" 형태의 감점 없는 재도전 유도 마이크로카피 템플릿.

### 11. 콩의 딜레마 (beandilemma)
- **재분류 필요**: 수학 문제풀이 게임이 아니라 **교사 주도 실시간 학급용 게임이론(공유지의 비극류) 활동 툴**(화이트팀 vs 레드팀 콩 배팅, MQTT 실시간 동기화, 5라운드). 도덕과 "공동체 정의" 연계.
- **잘 만든 이유(장르가 다름을 감안)**: "(수업 시간.. 갑자기 TV가 켜진다)" 식 5장 스토리텔링 인트로+효과음 텍스트+화면흔들림 연출. 라운드수/타이머/팀배정 방식/엑셀 붙여넣기 학생등록까지 교사용 설정 UX가 실사용 수준으로 꼼꼼. "승리팀 콩 개수는 비공개" 등 정보 비대칭 설계로 게임이론 학습효과 노림.
- **문제 생성**: 없음(퀴즈가 아니라 팀 배팅형 소셜 게임). `Math.random()`은 팀 자동배정 셔플용.
- **훔칠 것**: (1) "(수업 시간.. 갑자기 ○○)" 식 1인칭 서사 인트로 + 스킵 가능 옵션 패턴만 도입부 카피에 참고. (2) 이 게임 자체는 공장의 "혼자 하는 절차적 생성 수학 게임" 아키텍처와 무관하므로 문제생성/QA 참고 우선순위는 낮음.

# 공장에 반영할 인사이트 TOP 10

공장 파이프라인 단계: `10-design`(기획) → `15-judge`(컨셉 심사) → `20-art`(에셋 생성) → `30-build`(빌드) → `35-mathcheck`(수학 검산) → `40-review`(품질 게이트) → `45-fix`(수정)

1. **오답을 "오개념 역산"으로 생성하라** — box-run/rocket-charge/fusion/divide-farm/elevator/star-pickup 6개 게임 전부가 오답을 랜덤값이 아니라 "특정 자릿값 실수/받아올림 누락/몫 과대추정" 등 실제 학생 실수를 역산해서 만든다. → **`30-build.md`에 하드 요구사항으로 추가**: "오답 4개 중 최소 2개는 특정 계산 실수(자릿값 오류/받아올림 누락/인접수 혼동/역수 등)를 역산한 값이어야 하며, 그 오류 유형을 주석이나 변수명(`misconceptionId`류)으로 명시할 것." → **`35-mathcheck.md`에 체크 항목 추가**: 오답이 순수 랜덤인지 오개념 기반인지 판정.

2. **문제 생성은 "생성 후 검증"이 아니라 "제약 만족 풀에서 샘플링"** — divide-farm(`buildPool`), rocket-charge(`buildProblems`), star-pickup 모두 전수조합을 만든 뒤 단원 제약(받아올림 유무, 자릿수 범위)으로 필터링해 풀을 구성. → **`30-build.md`**: 문제 생성기 설계 원칙으로 "무작위 생성→사후 검증" 대신 "제약 조건을 만족하는 후보 전수 생성→그 안에서 셔플/샘플링"을 표준 패턴으로 명시.

3. **필산/장제법형 단원은 최종답 대신 절차를 스텝으로 쪼개라** — rocket-charge, fusion, elevator가 세로셈/장제법을 자리별 스텝 퀴즈로 쪼개고 실시간으로 세로셈판/장제법 박스에 반영한다. 최종답만 묻는 것보다 절차 이해도를 직접 훈련·측정. → **`10-design.md`**: 곱셈/나눗셈 필산 계열 슬롯에서는 "정답 하나 맞히기" 대신 "절차를 N단계로 쪼갠 스텝형 인터랙션"을 기본 컨셉 후보로 제시하도록 지침 추가.

4. **정답 시 보상은 절대 손해가 없어야 한다(`correctProtection`)** — star-pickup의 가중치 랜덤 보상 이벤트는 정답일 때 마이너스 이벤트를 코드로 원천 차단한다. → **`10-design.md`/`30-build.md`**: 랜덤 보상(가챠/이벤트) 설계 시 "정답 후 보상 풀에는 마이너스 결과를 포함하지 않는다"를 하드 규칙으로.

5. **처벌 없는 형성평가 루프를 기본값으로** — 매스몬 시리즈 전부가 생명/게임오버 없이 "1차 오답=힌트, 2차 오답=정답 공개 후 진행"으로 통일돼 있다. → **`10-design.md`** 기본 템플릿에 이 루프를 디폴트로 명시(현재 공장 게임들의 실패 처리 방식과 대조해 편차가 있으면 표준화).

6. **난이도별로 관용도 자체를 옵션화** — quiz-math-6-1-1이 쉬움=관용/어려움=오답 페널티를 사용자가 직접 고르게 한다. → **`10-design.md`**: 액션형/생존형 게임 컨셉에서는 시작 화면에 난이도 선택(관용도 차등)을 넣는 걸 옵션 패턴으로 제시.

7. **외부 상대경로 의존은 배포 즉시 죽는 리스크 — QA에서 자동 스캔하라** — box-run/fusion이 동일 시리즈의 다른 게임과 달리 `../_shared/...` 상대경로 스크립트를 못 찾아 시작 버튼 자체가 죽었다(try/catch 부재로 스크립트 전체 중단). 공장은 이미 "외부 CDN 금지·자기완결" 원칙이 있지만 이 사고는 **내부 상대경로 공유 모듈**에서 터졌다. → **`35-mathcheck.md` 또는 `40-review.md`**: 브라우저 콘솔 네트워크 탭에서 404 발생 시 반드시 must_fix high로 처리하는 체크(이미 "콘솔 에러 0개/404 0개" 규칙이 있으나, "그 404가 초기화 코드를 크래시시켜 시작 버튼이 죽는지"까지 실제 클릭 테스트로 확인하는 항목을 명시적으로 추가).

8. **정답 선택 후 "왜 그런가"까지 묻는 상위 배점 문항을 넣어라** — quadrilateral-rescue의 별 3종(발견/정답/설명) 보상 구조. → **`10-design.md`**: 도형/개념 단원 컨셉에서는 "정답 맞히기"에 더해 "이유 설명 선택형 문항"을 별도 보상 트랙으로 넣는 옵션을 제안 항목에 추가.

9. **좌표+허용오차 기반 실측 판정을 도형 단원의 표준 컴포넌트로** — quadrilateral-rescue가 하드코딩 미션이지만 정답 판정 자체는 벡터 연산+허용오차(4도)로 계산한다. → **`50-reference-scout.md`/`references/game-references.json`**: "좌표 기반 인터랙티브 지오메트리 판정" 메커닉을 도형 단원용 레퍼런스 카탈로그에 신규 항목으로 등록해 `10-design`에서 뽑아 쓸 수 있게 함.

10. **학습목표 체크리스트 게이팅 + 감점 없는 재도전 마이크로카피** — smart-shopping-mission의 "미션 조건 5개를 전부 체크해야 시작 가능" 온보딩과 "~초과했어요, ~해보세요" 소프트 피드백 문구. → **`10-design.md`**: 온보딩 설계 원칙에 "핵심 규칙 2~4개를 체크리스트로 제시하고 확인해야 시작 가능"을 추가. **`30-build.md`**: 오답/실수 피드백 문구 템플릿에 "감점 대신 재검토 유도" 톤(경고+구체적 재시도 방법 제시)을 표준 카피 가이드로 명시.

## 부가 발견 (참고용, TOP 10 외)
- 매스몬 7종은 하나의 "코어 게임 엔진(진행/피드백/보상/사운드/스코어보드 공통 모듈) + 단원별 문제 생성기/스킨" 아키텍처로 찍혀 나온다 — 우리 공장도 게임마다 처음부터 새로 짜기보다 **공통 러너/피드백/보상 컴포넌트 라이브러리**를 축적해 재사용하면 생산 속도와 품질 일관성을 동시에 얻을 수 있다. 단, 공유 모듈은 반드시 self-contained(인라인 또는 빌드타임 번들)로 넣어야 한다(인사이트 7 참조 — 상대경로 공유는 위험).
- beandilemma는 수학 문제풀이 게임이 아니라 실시간 멀티플레이 활동 툴이므로, 향후 유사 사이트를 "수학 게임" 레퍼런스로 넣을 때 장르 재분류 기준을 두는 게 좋다.
