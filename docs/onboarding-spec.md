# 첫 플레이 이해도 규격 (onboarding-spec)

> **원칙: 첫 판이 튜토리얼이다 — 읽게 하지 말고 해보게 하라.**

2026-09-01 첫 플레이 이해도 감사 결과, **신작 12작 전부 "완전 이해 가능"이 0개**였다
(yes 0 / partial 11 / no 1). 감사 방식은 "정답을 전혀 모르고 화면에서 눈에 띄는 것만
무작정 눌러 보는 순진한 학생"을 90초 돌린 뒤, 그 스크린샷만 보고 외부 모델(codex)이
`목표를 아는가 / 뭘 조작할지 아는가 / 수학이 어디 쓰이는지 아는가` 세 가지를 판정한 것이다.

QA 41개 항목을 다 통과하고 검수 80점을 넘은 게임들이 전부 여기서 걸렸다. 즉 **기존
게이트는 "동작하는가"만 봤지 "이해되는가"를 본 적이 없다.** 이 문서가 그 구멍을 메운다.

교차 패턴 4가지가 12작에 반복됐다:

| # | 패턴 | 몇 작에서 | 학생이 겪는 일 |
|---|---|---|---|
| ① | **태그라인이 조어·은유** | 12/12 | 시작 전에 무슨 게임인지 예고가 안 된다 |
| ② | **온보딩이 텍스트뿐** (조작 대상 포인팅 없음) | 7/12 | 글은 읽었는데 화면의 **어디**를 눌러야 하는지 모른다 |
| ③ | **온보딩 부재** (도움말 링크만 있고 자동 안내 없음) | 4/12 | 아무 설명 없이 플레이 화면에 던져진다 |
| ④ | **조작 무반응 → "고장" 오인** | 8/12 | 눌러도 아무 일이 없어 게임이 망가진 줄 알고 그만둔다 |

## 1. 필수 요건 (a~g) — 하나라도 빠지면 온보딩 미달이다

### (a) 시작 직후 첫 문제에서 **조작 대상을 시각적으로 가리킨다**

글로 "손잡이를 아래로 끌어"라고 쓰는 것으로는 부족하다. 화면의 **그 물건 위에**
손가락 아이콘 / 화살표 / 맥동(pulse) 링 / 스포트라이트 중 하나를 얹어라.

- 가리키는 대상은 **좌표가 아니라 실제 오브젝트**여야 한다 — 오브젝트가 움직이면
  포인터도 따라가야 한다. (레이아웃이 바뀌면 어긋난 허공을 가리키게 된다)
- 드래그가 필요하면 **경로를 보여줘라**: 손가락이 시작점 → 도착점으로 실제로 움직이는
  1.2초 루프 애니메이션. 점선 궤적 + 도착 지점의 유령 실루엣.
- 「맞춰밀기」는 3단계 텍스트 온보딩이 있는데도 `high` 판정을 받았다. 이유가 정확히
  이것이다 — *"화면 아래 장치 전체가 손잡이처럼 보여 정확히 어디를 잡아야 하는지 모호하다."*

### (b) 첫 조작을 **실제로 해볼 때까지 진행을 대기**한다

설명 → `다음` → 설명 → `다음` → 실전 은 온보딩이 아니라 팝업 3장이다.
**마지막 단계는 반드시 "직접 한 번 해보기"**여야 하고, 그때까지:

- 타이머·적·낙하 같은 **압박은 정지**한다.
- 목숨은 깎이지 않는다.
- 학생이 그 조작을 성공하면 **즉시 눈에 보이는 보상**(오브젝트가 실제로 움직임 + 밝은
  플래시 + 짧은 상승음)을 주고 온보딩을 닫는다.
- 첫 조작을 8초 넘게 안 하면 포인터를 **더 크게 다시** 재생한다 (한 번 재생하고 끝내지 마라).

### (c) 목표 1문장이 화면에 **상시** 있다

온보딩이 닫힌 뒤에도 남아 있어야 한다. 팝업으로 스쳐 지나가면 학생은 이미 잊었다.

- 형식: **`무엇을` + `어떻게 하면` + `무슨 일이 생긴다`** 한 문장. 20자 내외.
  - ✅ "강 폭에 맞게 판자를 놓고 **건너기**를 눌러요"
  - ❌ "관이 뒤섞였어 — 나누는 조각만큼 묶어 베어 줘" (뜻도 조작도 안 보인다)
- 게임 세계관 어휘가 학생이 모르는 말이면 **세계관을 버려라.** 「묶음칼」의 '관',
  「층수켜기」의 '총의 칸·스캔 막대', 「맞춰밀기」의 '몫 드럼'은 전부 판정에서
  "낯설고 구체적인 행동을 알려주지 못한다"고 지적당했다.

### (d) 수학이 어디 쓰이는지 **첫 정답 순간에 드러난다**

첫 정답은 "맞았다"로 끝내지 말고 **왜 맞았는지를 1초 동안 보여줘라.**

- 계산식이 정답 오브젝트 위에 잠깐 뜬다 (`3/5 m × 5장 = 3 m` 처럼 실제 값과 함께).
- 정답 오브젝트와 문제 문장의 해당 부분을 **같은 색으로 동시에 하이라이트**한다.
- 「층수켜기」는 *"비슷하게 무작정 누른 흐름인데 이번에는 100점을 얻는다. 성공 이유가
  제시되지 않아 우연히 맞힌 것으로 보인다"* 는 판정을 받았다. **정답에 설명이 없으면
  정답도 학습이 아니다.**
- 오답도 같다. "틀렸어요"만으로는 학습이 안 된다 — **정답 상태를 0.8초 보여주고**
  넘어가라. 좌표(`(0,0)`)나 내부 용어로 실패를 통보하지 마라.

### (e) **어떤 탭에도 무반응 금지**

이게 12작 중 8작을 무너뜨린 항목이고, 자동 QA로도 안 잡힌다
(`input.real` 은 "유효 입력이 먹히는가"만 본다).

- 게임 영역 **어디를 눌러도** 최소 반응이 있어야 한다:
  - 유효하지 않은 대상 → 그 자리에 짧은 리플(ripple) + 진짜 대상 쪽으로 화살표 한 번.
  - 지금 조작 불가 상태 → 화면 흔들림이 아니라 **대상의 좌우 흔들림(shake 6px, 200ms)** +
    "지금은 ○○부터 해요" 한 줄.
  - 드래그해야 하는데 탭했다 → 손가락 경로 힌트를 즉시 재생.
- **금지**: 500ms 안에 아무 픽셀도 안 바뀌는 입력. 학생은 "고장 났다"로 읽고 나간다.
- 자가 점검: `factory/lib/firstplay/harness.mjs` 를 돌려 나온 프레임 중 **연속 3장이
  사실상 같은 화면**이면 이 항목 실패다.

### (f) 태그라인 작법 — 조어·은유 금지, **동사 + 대상**

태그라인은 분위기 문구가 아니라 **조작 예고**다. 12자 이내는 유지하되:

- ✅ **`동사 + 대상` 형태로 실제로 하는 일을 써라.**
  - "송판을 10장씩 묶어 올려라"
  - "판자를 놓아 강을 건너라"
  - "연결쇠를 눌러 열차를 갈라라"
- ❌ **금지 목록** (전부 실제 지적 사례다):
  - 조어: `내려탁`, `짝점`, `승판올려` — 뜻을 짐작할 수 없다.
  - 은유·말장난: `한 칼이 한 몫`, `한 편이 두 길`, `일곱 군데만 풀어`.
  - 위협만 하는 문구: `빗나가면 탈락`, `한 칸만 어긋나면 폐기`, `한 변만 어긋나면 끝`.
    → 무엇을 왜 맞추는지가 없다. '폐기'·'탈락' 같은 말은 초등학생에게 위협적이다.
  - 결과만 말하기: `잠기기 전에 켜` — 무엇을 켜는지가 없다.
- **제목도 같은 검사를 받는다.** 붙여 쓴 조어(`층수켜기`, `소수덱폭주`)는 저학년이
  즉시 못 읽는다. 장식 글꼴로 뭉개져 읽기 어려우면 그것도 감점이다.
- **자가 검사 한 줄**: 게임을 모르는 사람에게 제목+태그라인만 보여주고
  *"이 게임에서 손가락으로 뭘 하게 될 것 같아?"* 를 물었을 때 답이 나와야 한다.
  안 나오면 다시 써라.

### (g) 「어떻게 놀아요?」는 **보조 수단이지 온보딩 대체가 아니다**

`docs/title-screen-spec.md` 의 접이식 도움말 링크는 **재방문자용 복습 창구**다.

- 첫 실행에서 이 링크만 있고 자동 안내가 없으면 **온보딩 부재(패턴 ③)** 로 친다.
  「상자해제」·「소수 덱폭주」·「면을 대!」·「짝점」이 전부 이 사유로 걸렸다.
- 링크는 작고 눈에 안 띈다 — 판정문 그대로: *"아래의 작은 '어떻게 놀아요?' 문구는
  눈에 잘 띄지 않는다."* 첫 판은 링크를 누를 이유 자체를 학생이 모른다.
- 규칙: **첫 실행 = 자동 인게임 온보딩(스포트라이트+포인팅+해보기)**,
  **재방문 = CTA 즉시 시작 + `어떻게 놀아요?` 로 언제든 다시 열기.**

## 2. 잘된 사례 — 기존 게시작에서 베낄 것

고득점 게시작 9작(`lantern-disk` 92 / `overlay-snap` 92 / `boundary-rush` 91 /
`decimal-smash` 91 / `wrap-pop` 91 / `cube-merge-factory` 90 / `honey-cups` 90 /
`stone-hop` 90 / `tide-checkpoint` 90)의 온보딩 코드를 훑은 결과다.

**먼저 알아야 할 것: 9작 전부가 똑같은 하네스를 쓴다** — `#onb` + `#onbHole`(스포트라이트
구멍) + 3단계 모달 + `localStorage['onboardingSeen:<slug>']` + 타이틀의 「어떻게 놀아요?」.
**그러니까 이 모달은 잘한 게 아니라 기준선이다.** 12작도 다 가지고 있었고 전부 떨어졌다.
갈라지는 지점은 **모달이 닫힌 뒤 플레이 중에 무엇이 남는가**다. 아래 셋이 그걸 가졌다.

### 사례 1 — `cube-merge-factory` (네모공장): 안내가 끊기지 않는다 (a)(b)(c)(e)

**① 첫 성공 전까지 안 사라지는 배너, 성공하는 순간 "다음 할 일"로 교체**

### 사례 2 — `honey-cups` (꿀몇잔): 무효 입력을 **무시하지 말고 거절**한다 (a)(d)(e)

요건 (e) 의 교과서다. 12작 중 8작을 무너뜨린 "눌러도 아무 일 없음"의 정답이 여기 있다.

```js
// public/g/honey-cups/index.html:2073
function refusePlan(which, msg) {
  var stepper = $(which === 'q' ? 'qStepper' : 'rStepper');
  if (stepper) {
    stepper.classList.remove('refuse');
    void stepper.offsetWidth;          // 리플로우 강제 = 연속 거절에도 매번 재점화된다
    stepper.classList.add('refuse');
  }
  coachSay(msg);                       // 왜 안 되는지 한 문장
  sfxRefuse();                         // 전용 거절음 beep(240,.09,'square',.12,160)
}
function nudgePlan(which, dir) {
  var nq = S.planQ + dir;
  if (nq > qMax) { refusePlan('q', '통에 든 꿀보다 많이 채울 수 없어요.'); return; }
  if (nq < qMin) { refusePlan('q', '잔 수는 0보다 작아질 수 없어요.'); return; }
  S.planQ = nq;
}
```

### 조연 패턴 2개 — 싸고 효과가 크다

- **`wrap-pop` — 확정 전 2단 탭.** 첫 탭은 확정이 아니라 「둘레 자」가 눈금을 세며 한 바퀴
  도는 애니메이션이고(= 조작에 즉각 가시 반응 + 수학 노출), 두 번째 탭이나 「감기!」 버튼이
  확정이다. `armOrWrap()` index.html:1030, 자 렌더 index.html:1331.
  → 첫 탭이 실수로 목숨을 깎지 않으면서도 **화면이 반드시 반응한다**. 요건 (e) 와 실수
  관용도를 한 번에 해결한다.
- **`stone-hop` / `cube-merge-factory` — 결정론적 첫 문제.** 1번 연못 첫 줄은 무조건
  `tutorialRow()`(3 이상 6 미만, 경계값 3·6을 각각 정답/오답으로 배치)로 고정한다
  (stone-hop index.html:831, 858). `cube-merge-factory` 의 `firstPairDims`(index.html:1753)
  도 첫 두 스폰이 반드시 짝이 되도록 보장한다.
  → **첫 화면이 매번 같으니 안내 문구와 화면이 절대 어긋나지 않는다.** 첫 문제를 난수에
  맡기면 포인팅도 설명도 어긋날 수 있다.

### 반례 — 이 정도로는 부족하다

`tide-checkpoint`(90점)는 모달 + `#rotateHint` 회전 안내가 전부고, `decimal-smash`(91점)는
모달 + `ruleCard` pulse 뿐이다(「힌트 방울」은 온보딩이 아니라 레벨4 메커닉이다).
`overlay-snap`·`stone-hop` 은 첫 문항을 고정하고 문장을 띄우지만 **가리키기가 없다.**
**점수가 높다고 온보딩이 좋은 게 아니다** — 이 규격은 점수와 독립적으로 본다.
