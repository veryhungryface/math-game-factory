# 플레이 화면 판형 규격 (playfield-spec)

> 제정: 2026-08-28. 이 문서가 **구 규범("세로형 게임은 중앙 640px 컬럼+레터박스")을 폐기하고 대체**한다.
> `docs/design-bible.html` 3.4절·사고 4가 이 문서를 참조한다. 신작 빌드와 구작 와이드 전환
> 캠페인 모두 이 규격을 그대로 따른다.

## 0. 왜 바꾸나 (2026-08-28 전 게임 감사)

사용자 피드백: "거의 모든 게임이 모바일처럼 중앙에서만 플레이되고 디자인이 천편일률적이다.
경쟁작(킹수학)보다 퀄리티가 떨어져 보인다."

감사 결과(게시 20작): 진짜 가로 재배치는 9작뿐. 4작은 배경만 넓고 플레이는 중앙 고정,
7작은 가로 분기 자체가 없다. 20작 전부 분기 조건이 종횡비(W>=H)뿐이라 **세로로 긴
데스크톱 창에서는 와이드 게임조차 모바일 레이아웃**이 나온다. 원인은 규범이었다 —
구 바이블이 "중앙 640px 컬럼+레터박스"를 표준으로 명문화했기 때문에, 캔버스는 풀블리드로
깔아 놓고 그리기 좌표를 560~680px 중앙 컬럼에 캡하는 패턴이 전 게임에 복제됐다.

## 1. 원칙

**플레이 영역이 화면을 활용한다.** 세로폰(390×844)이 기준 판형이되, 가로·데스크톱
(1280px+)에서는 레이아웃이 **재배치**되어야 한다. 중앙 좁은 컬럼 + 좌우 빈 거터는 실격이다.

- "재배치"란 확대가 아니다. HUD·스테이지·컨트롤 존이 와이드에서 **다른 자리**로 이동하고,
  플레이필드 자체가 넓어진 폭을 쓰는 것이다. 세로 레이아웃을 가운데 놓고 배경만 칠하면 실격.
- 레터박스(좌우 거터)는 초와이드(1440px+)에서 잔여 폭에만 허용된다. 1280×800에서 빈 거터가
  화면 폭의 30%를 넘으면 안 된다.
- 세로폰 회귀 금지: 와이드 대응이 390×844 레이아웃을 깨뜨리면 안 된다.

## 2. 표준 메커니즘 — `--stageW` + `html.land`

기존 게시작 중 가장 정교한 패턴(등불을 켜 lantern-disk, 파도 검문소 tide-checkpoint,
가름돌 split-stone)에서 발췌한 표준 레시피다. 그대로 복붙해서 시작해라.

### 2.1 CSS — 스테이지 변수와 land 스코프

```css
:root{
  /* 게임 성격 따라 1280~1440 허용. 기본 1280 */
  --stageW: min(100vw, 1280px);
  --stageX: calc((100vw - var(--stageW)) / 2);
}
/* 와이드 분기는 전부 html.land 스코프 아래에 모은다 */
html.land #hud{ left:var(--stageX); width:min(460px, calc(var(--stageW)*0.36)); }
html.land #panel{
  left:calc(var(--stageX) + var(--stageW) - min(320px, calc(var(--stageW)*0.26)) - 12px);
  width:min(320px, calc(var(--stageW)*0.26));
}
html.land #ctrl{ left:var(--stageX); width:min(700px, calc(var(--stageW)*0.54)); }
```
(실전 예: `public/g/lantern-disk/index.html:280-298`, `tide-checkpoint/index.html:231-235`)

### 2.2 JS — land 토글과 스테이지 계산 (resize 시마다)

```js
function layout(){
  const W = innerWidth, H = innerHeight;
  // ★ 종횡비뿐 아니라 폭 기준도 land 진입 조건이다.
  //   세로로 긴 데스크톱 창(예: 1280×1400)도 와이드로 취급해야 한다.
  S.land = (W >= H && W >= 640) || W >= 1024;
  document.documentElement.classList.toggle('land', S.land);

  const STAGE = Math.min(W, 1280);          // --stageW 상한과 반드시 일치시켜라
  const SX = Math.round((W - STAGE) / 2);
  S.stageW = STAGE; S.stageX = SX;
  const root = document.documentElement;
  root.style.setProperty('--stageW', STAGE + 'px');
  root.style.setProperty('--stageX', SX + 'px');

  // 캔버스 그리기 좌표도 같은 값을 쓴다 — CSS 존과 캔버스 플레이필드가 어긋나면 안 된다.
  if (S.land) {
    S.play = { x: SX + 12, y: 58, w: STAGE - 24, h: Math.max(150, H - 100 - 58) };
  } else {
    S.play = { x: 0, y: 150, w: W, h: Math.max(150, H - 248 - 150) };
  }
}
window.addEventListener('resize', layout);
window.addEventListener('orientationchange', () => setTimeout(layout, 120));
```
(실전 예: `lantern-disk/index.html:870-896` — 단, lantern-disk의 조건은 `W>H && W>=640`
구식이다. 신규·전환 코드는 위처럼 **`|| W >= 1024`를 반드시 포함**해라.)

### 2.3 초와이드 거터 (1440px+ 잔여 폭)

스테이지 상한을 넘는 폭은 배경 톤을 살짝 눌러 무대 밖임을 표시한다:

```js
function drawGutter(ctx, W, H){
  if (!S.land || S.stageW >= W - 2) return;
  ctx.fillStyle = 'rgba(0,0,0,0.28)';           // 게임 팔레트에 맞는 색으로
  ctx.fillRect(0, 0, S.stageX, H);
  ctx.fillRect(S.stageX + S.stageW, 0, W - (S.stageX + S.stageW), H);
}
```
(실전 예: `lantern-disk/index.html:1954-1957`)

### 2.4 규칙 요약

1. `--stageW: min(100vw, 1280px)` 기본. 필드가 넓어야 이득인 게임(자유 비행·러너)은
   1440px까지, 무대 집중형은 1360px까지 허용. JS `Math.min(W, N)`과 CSS 상한을 일치시켜라.
2. land 진입 조건: `(W >= H && W >= 640) || W >= 1024`. **폭 1024px 이상이면 종횡비와
   무관하게 land다.**
3. HUD/스테이지/컨트롤을 존(zone)으로 나누고, land에서 존을 재배치해라 (3장 원형 참조).
4. 터치 타깃 44px 이상은 land에서도 유지. 폰트·오브젝트 크기는 stageW 기준으로 스케일하되
   상한을 둬라 (초와이드에서 거대해지면 안 된다 — stone-hop 교훈).
5. QA가 1280×800에서 `html.land` 활성 여부를 기계 검사한다 (`layout.wide1280`). land 클래스를
   못 쓰는 특수 구조(예: 3D 카메라 게임)면 `window.__GAME_TEST__.getLayout()`으로
   `{ land: true, playW: <플레이필드 px 폭> }`을 노출해라.

## 3. 와이드 원형 3종 — "다 똑같다"를 피하는 법

와이드 재배치가 전부 같은 모양이면 다양성 문제가 재발한다. 게임 메커닉에 따라 아래
3원형 중 하나를 고르고, 기획서·전환 계획에 어느 원형인지 명시해라.

### ① 파노라마형 (Panorama) — 플레이필드 자체가 가로로 넓어진다

적용: 러너·회피·자유 비행·물리 필드형. 오브젝트가 화면을 돌아다니는 게임.
넓어진 폭 = 더 넓은 시야·더 많은 동시 오브젝트 = 게임성 향상.

```
┌────────────────────────────────────────────────┐
│ HUD(좌상)                          보조정보(우상) │
│                                                │
│        ←———— 플레이필드 (stageW 전체) ————→        │
│   오브젝트가 가로 전폭을 실제로 사용                  │
│                                                │
│              컨트롤 (하단 중앙/전폭)                │
└────────────────────────────────────────────────┘
```
핵심: 스폰 영역·이동 범위·레인 폭을 stageW에서 파생시켜라. 세로 레이아웃의 좌표 상수를
비율로 바꾸는 것이 작업의 대부분이다.

### ② 2단 분할형 (Split) — 좌 스테이지 + 우 정보/컨트롤 패널

적용: 퍼즐·조작·제작형. "작업 대상"과 "주문서/선택지/도감"이 분리돼 있는 게임.
세로에서는 위(스테이지)/아래(패널)로 쌓이던 것을 좌/우로 펼친다.

```
┌────────────────────────────────────────────────┐
│ HUD (상단 전폭 또는 좌측 상단)                      │
│ ┌──────────────────────────┐ ┌───────────────┐ │
│ │                          │ │  주문/문제 카드  │ │
│ │   스테이지 (stageW 60~70%) │ │  선택지·게이지   │ │
│ │   조작 대상이 크게 보인다     │ │  진행/도감      │ │
│ │                          │ │  (30~40%)     │ │
│ └──────────────────────────┘ └───────────────┘ │
└────────────────────────────────────────────────┘
```
핵심: 패널 폭은 `min(320~460px, stageW*0.26~0.4)`. 스테이지가 커진 만큼 조작 대상
(그리드·잔·캔)을 확대해라 — 패널만 옮기고 스테이지를 안 키우면 실격이다.

### ③ 극장형 (Theater) — 중앙 무대 확대 + 좌우 보조 존

적용: 무대형 — 하나의 중심 오브젝트(탑·무대·작업대)를 바라보며 조작하는 게임, 3D 게임.
중앙 무대를 확대하고, 세로에서 무대를 가리던 HUD·기록·힌트를 좌우 여백 존으로 밀어낸다.

```
┌────────────────────────────────────────────────┐
│ ┌──────────┐ ┌────────────────┐ ┌──────────┐  │
│ │ 문제/지시   │ │                │ │ 기록/힌트   │  │
│ │ 카드       │ │   중앙 무대      │ │ 진행 현황   │  │
│ │ (좌 존)    │ │  (확대·집중)     │ │ (우 존)    │  │
│ └──────────┘ │                │ └──────────┘  │
│              └────────────────┘               │
│              컨트롤 (하단 중앙)                   │
└────────────────────────────────────────────────┘
```
핵심: 무대가 실제로 커져야 한다(3D면 카메라 거리·FOV를 land에서 재조정). 좌우 존은
세로에서 오버레이·하단에 있던 정보를 **옮겨온** 것이어야지, 새 장식을 채우는 자리가 아니다.

## 5. 검증 기준 (QA + 검수)

전환·신작 공통. 아래를 통과해야 게시한다.

1. **1280×800**: `html.land`(또는 getLayout의 land) 활성 — QA `layout.wide1280` 항목.
   플레이 영역이 재배치돼 있고, 좌우 빈 거터 합이 화면 폭의 30% 이하.
2. **1920×1080**: 스테이지가 stageW 상한까지 확장, 잔여 폭은 거터 처리(2.3절). 레이아웃
   깨짐(겹침·과대 폰트) 없음.
3. **390×844 회귀 없음**: 세로폰 레이아웃이 전환 전과 동등해야 한다. 가로 스크롤 0.
4. **터치 타깃 44px 이상** — land 레이아웃에서도 유지.
5. QA 스크린샷 4종(mobile/tablet/desktop-1280/wide)을 검수관이 육안 확인 — 1280에서
   중앙 좁은 컬럼+빈 거터면 비주얼 감점 + must_fix high.
