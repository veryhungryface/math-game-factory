# 구작 5게임 신설 규범 소급 감사

- 감사일: 2026-08-20
- 범위: `public/g/{rounding-dash,jelly-gate,symmetry-breaker,decimal-smash,cube-merge-factory}/index.html`
- 기준: `factory/prompts/30-build.md` 후반부의 물리 은유 정합성·연출 감정 어휘 분리·실시간 액션 중 계산 부하 규칙과 `factory/prompts/40-review.md` 후반부의 추가 게이트를 중심으로, 요청된 7개 기준을 소급 적용했다.
- 표기: 심각도는 `높음 > 중간 > 낮음`, 수정 난이도는 `S < M < L`이다. 감사만 수행했으며 대상 게임 코드는 수정하지 않았다.

## 1. 어림 대시 (`rounding-dash`)

### 위반 목록 (5건)

1. **[높음] 정답 통과에 화면 흔들림을 사용한다.** 일반 통과와 경계 정답 모두 `G.shake`를 설정하고, 렌더 단계에서 화면 전체 좌표를 무작위 이동한다. 정답의 빛·파티클과 오답 전용이어야 할 흔들림이 한 경로에 섞인다.  
   - 코드 근거: `public/g/rounding-dash/index.html:891-932`, `public/g/rounding-dash/index.html:1871-1873`  
   - 수정 난이도: **S**

2. **[높음] 낙하 시간 압박 아래 계산형 어림·역추적 문제를 내지만 사고 시간 동안 압박을 멈추거나 충분히 감속하지 않는다.** 3~7단계에서 세·네 자리 수의 올림/버림/반올림, 역추적, 실생활 어림을 1.9~2.9초 낙하 안에 처리하게 한다. 감속은 플레이어가 이미 정답 경계에 도착한 막판에만 발생하며, 길게 눌러 답을 엿보면 오히려 벽이 2~3배 빨라진다.  
   - 코드 근거: `public/g/rounding-dash/index.html:460-469`, `public/g/rounding-dash/index.html:522-597`, `public/g/rounding-dash/index.html:1337-1344`  
   - 수정 난이도: **M**

3. **[중간] 받침을 무시한 조사 병기 문자열이 실제·표본 문제에 남아 있다.** `관객 3250은(는)`, `3274을(를)`처럼 읽히므로 문장 품질과 조사 정확성 기준을 어긴다.  
   - 코드 근거: `public/g/rounding-dash/index.html:576-578`, `public/g/rounding-dash/index.html:1940-1944`  
   - 수정 난이도: **S**

4. **[중간] 실생활 문제의 답 레인에서 단위가 빠진다.** 생성 데이터에는 `개`, `cm`, `명` 맥락이 있지만 벽의 선택지는 숫자만 그리며, 해당 단위 필드는 판정·표시에 사용되지 않는다. 특히 “몇 cm?” 또는 “개수”를 묻고 단위 없는 숫자 칸으로 답하게 된다.  
   - 코드 근거: `public/g/rounding-dash/index.html:568-597`, `public/g/rounding-dash/index.html:1636-1644`  
   - 수정 난이도: **S**

5. **[낮음] 초등 화면 문구로는 설명 없는 ‘역추적’이 어렵다.** 단계명과 개념명에 바로 노출되지만 쉬운 풀이말이 함께 나오지 않는다.  
   - 코드 근거: `public/g/rounding-dash/index.html:547-565`, `public/g/rounding-dash/index.html:754-756`  
   - 수정 난이도: **S**

### 확인 결과(위반 없음)

- 무게·균형·등확률을 전제하는 물리 은유는 사용하지 않는다.
- 모든 벽은 생성 시 통과 레인을 보장하고, 연료가 없어도 드래그 도달 가능성을 고려해 시작점을 고르므로 구조적 교착은 확인되지 않았다 (`:475-495`, `:617-635`).
- 채점용 장식 확인 버튼은 없다.

## 2. 젤리 게이트 (`jelly-gate`)

### 위반 목록 (5건)

1. **[높음] 정답/성공 경로에 화면 흔들림이 들어간다.** 최적 게이트 선택 후 분리 연출과 자물쇠 벽 통과·유예 통과 모두 `G.shake`를 설정하며, 캔버스 전체에 적용된다.  
   - 코드 근거: `public/g/jelly-gate/index.html:1087-1120`, `public/g/jelly-gate/index.html:1169-1174`, `public/g/jelly-gate/index.html:1198-1214`, `public/g/jelly-gate/index.html:1585-1587`  
   - 수정 난이도: **S**

2. **[중간] 정답이어도 젤리 수가 줄면 오답색(붉은색) 플래시를 사용한다.** 모든 선택지가 1보다 작은 초반 구간에서는 최적 정답도 감소할 수 있는데, 연출 색은 정답 여부가 아니라 증감만 보고 정해진다. 정답=빛/상승, 오답=차단이라는 감정 어휘가 분리되지 않는다.  
   - 코드 근거: `public/g/jelly-gate/index.html:448-489`, `public/g/jelly-gate/index.html:1091-1119`, `public/g/jelly-gate/index.html:1169-1174`  
   - 수정 난이도: **S**

3. **[높음] 누적식에서 생략한 항을 둔 채 등식을 표시한다.** 5번째 항부터 화면에는 시작 수, 말줄임표, 마지막 4개 곱만 남기면서 현재 결과와 `=`로 연결한다. 생략된 곱셈항 없이는 좌변과 우변이 같지 않아, 보이는 수식 자체가 거짓이 된다.  
   - 코드 근거: `public/g/jelly-gate/index.html:988-997`, `public/g/jelly-gate/index.html:408-417`  
   - 수정 난이도: **M**

4. **[중간] 게임오버 도움말이 ‘게이트 두 개’라고 하지만 실제 화면은 3~4개다.** 화면 선택지 수와 피드백 문구의 수가 일치하지 않는다.  
   - 코드 근거: `public/g/jelly-gate/index.html:534-542`, `public/g/jelly-gate/index.html:1316-1322`  
   - 수정 난이도: **S**

5. **[중간] ‘조금 모자라도 한 번은 봐준다’는 안내가 실제 횟수 규칙과 다르다.** 유예 통과는 별도의 1회 소모 상태 없이 `graceMin` 이상이면 매 구간·매 재도전에서 반복 적용된다.  
   - 코드 근거: `public/g/jelly-gate/index.html:318-324`, `public/g/jelly-gate/index.html:1198-1208`, `public/g/jelly-gate/index.html:1347-1353`  
   - 수정 난이도: **S**

### 확인 결과(위반 없음)

- 게이트가 젤리를 분수배로 늘리거나 줄인다는 계약과 결과 수가 화면 식에 명시되어 있어, 별도의 등질량·등확률 가정 충돌은 확인되지 않았다.
- 핵심 판단은 분수의 크기 비교이며 정확한 곱 계산을 실시간으로 입력하게 하지는 않는다. ‘정밀’ 감속도 제공된다 (`:1475-1481`, `:1504-1529`).
- 스폰 고갈·만석형 보드가 아니며 채점용 장식 확인 버튼도 없다.

## 3. 대칭 브레이커 (`symmetry-breaker`)

### 위반 목록 (2건)

1. **[높음] 거의 모든 정답 경로가 화면 흔들림을 호출한다.** 올바른 접기, 올바른 180° 회전, 합동 조각 선택, 게이트 클리어, 결정 완성까지 흔들림이 단계적으로 커진다. 주석에도 정답 콤보에 따른 `screen-shake-tiered`라고 명시되어 신설 규범과 정면 충돌한다.  
   - 코드 근거: `public/g/symmetry-breaker/index.html:997-1018`, `public/g/symmetry-breaker/index.html:1066-1075`, `public/g/symmetry-breaker/index.html:1094-1103`, `public/g/symmetry-breaker/index.html:1112-1125`, `public/g/symmetry-breaker/index.html:1350-1352`  
   - 수정 난이도: **S**

2. **[낮음] 결과 화면의 ‘결정 성소’는 설명 없는 어려운 한자어다.** 게임 진행에 필요한 말은 아니지만 초등 대상 결과 문구의 즉시 이해를 방해한다.  
   - 코드 근거: `public/g/symmetry-breaker/index.html:332-337`  
   - 수정 난이도: **S**

### 확인 결과(위반 없음)

- 접기·회전은 화면에서 직접 수행하고 정답 축/중심도 오답 뒤에 실제로 그려 주므로, 화면에 없는 수나 숨은 물리 가정을 인용하지 않는다 (`:860-872`).
- 제한 시간은 공간 관계 식별에 걸리며 무거운 수치 계산을 요구하지 않는다.
- `버리기`는 ‘대칭이 전혀 없음’을 판단하는 채점 입력이므로 장식 확인 버튼이 아니다.
- 스폰·합체 자원형 게임이 아니어서 구조적 교착은 확인되지 않았다.

## 4. 소수 스매시 (`decimal-smash`)

### 위반 목록 (3건)

1. **[높음] 임의 소수 곱셈을 움직이는 방울과 12초 라운드 압박 속에서 계산하게 하며, 사고 시간 동안 정지·감속이 없다.** 3단계부터 `0.2~9.7 × 0.2~9.7` 꼴을 만들고, 5단계는 이를 연쇄 계산한다. 방울 이동·라운드 타이머는 계속 진행하며 감속은 정답을 이미 맞힌 뒤 70ms 히트스톱뿐이다. 신설 계산 부하 규칙의 직접 위반이다.  
   - 코드 근거: `public/g/decimal-smash/index.html:640-650`, `public/g/decimal-smash/index.html:674-706`, `public/g/decimal-smash/index.html:825-860`, `public/g/decimal-smash/index.html:1261-1295`  
   - 수정 난이도: **M**

2. **[높음] 온보딩은 오답 방울을 그어도 목숨이 줄지 않는다고 안내하지만 실제로는 목숨을 깎는다.** 안내를 믿고 플레이하면 세 번의 오답으로 게임오버가 될 수 있어 문구와 판정이 정반대다.  
   - 코드 근거: `public/g/decimal-smash/index.html:799-807`, `public/g/decimal-smash/index.html:862-875`, `public/g/decimal-smash/index.html:1056-1063`  
   - 수정 난이도: **S**

3. **[높음] ‘자연수를 곱하면 무조건 커져요’는 화면 문장 자체가 거짓이다.** 자연수 1을 곱하면 값이 그대로이므로 숨은 조건은 ‘1보다 큰 자연수’다. 생성기는 2~9만 사용하지만 그 제한을 문구에 명시하지 않아 일반 명제로 오개념을 만든다.  
   - 코드 근거: `public/g/decimal-smash/index.html:628-637`, `public/g/decimal-smash/index.html:652-658`  
   - 수정 난이도: **S**

### 확인 결과(위반 없음)

- 정답 경로에는 파티클·상승 점수·밝은 플래시만 있고 `triggerShake` 호출은 폭탄·오답 경로에만 있어 감정 어휘 분리는 통과한다 (`:810-875`).
- 정답 슬롯이 모두 폭탄으로 바뀌는 극단 상황에는 강제 정답 슬롯 복구가 있어 진행 고갈은 없다 (`:754-772`).
- 채점용 장식 확인 버튼과 물리·등확률 은유는 없다.

## 5. 네모공장 (`cube-merge-factory`)

### 위반 목록 (4건)

1. **[높음] 길이 치수와 길이 합 답에서 `cm` 단위가 일관되게 빠진다.** 게임 주문서와 타일은 `가로·세로·높이` 숫자만 표시하고, 표본 문제 중 ‘모든 모서리 길이의 합은 몇 cm’의 선택지·정답도 숫자 문자열만 반환한다. 내부 주석이 `cm 단위`라고 계약한 것과 화면 표기가 다르다.  
   - 코드 근거: `public/g/cube-merge-factory/index.html:627-637`, `public/g/cube-merge-factory/index.html:1026-1030`, `public/g/cube-merge-factory/index.html:1060-1063`, `public/g/cube-merge-factory/index.html:2224-2245`, `public/g/cube-merge-factory/index.html:2293-2316`, `public/g/cube-merge-factory/index.html:2454-2460`  
   - 수정 난이도: **S**

2. **[중간] 표본 문제 생성기에 받침 무시 조사 병기가 남아 있다.** `면은(는)`, `꼭짓점이(가)`처럼 그대로 노출된다.  
   - 코드 근거: `public/g/cube-merge-factory/index.html:2462-2466`  
   - 수정 난이도: **S**

3. **[높음] 특정 전개도 그림 없이 ‘마주 보는 면은 같은 줄에서 한 칸 건너’라고 일반화한 문제는 성립하지 않는다.** 전개도 배치에 따라 마주 보는 면의 평면상 위치가 달라지며, 어떤 면을 기준으로 하는지도 명시하지 않았다. 화면에 필요한 도형이 없는 상태에서 고정 답을 단정한다.  
   - 코드 근거: `public/g/cube-merge-factory/index.html:2476-2479`  
   - 수정 난이도: **M**

4. **[중간] 4단계 모서리 길이 합 계산도 주문 타이머·스폰 압박 중에 진행된다.** 작은 수이고 제한 시간이 32초라 즉각적인 과부하는 낮지만, 계산 문제 동안 압박 정지·감속이나 풀이 타일은 없다.  
   - 코드 근거: `public/g/cube-merge-factory/index.html:878-890`, `public/g/cube-merge-factory/index.html:1078-1082`, `public/g/cube-merge-factory/index.html:2355-2391`  
   - 수정 난이도: **M**

### 확인 결과(위반 없음)

- 정답 병합·배송은 상승 파티클·빛 확산을 쓰고, 화면 흔들림은 오합체·오배송에만 연결되어 감정 어휘 분리를 통과한다 (`:1561-1569`, `:1588-1640`, `:1689-1764`).
- 빈칸 2개 이하에서 스폰을 멈추고, 합체·배송이 모두 불가능하면 2.2초 뒤 타일 하나를 무료 제거한다. 주문 지향 스폰과 첫 짝 보장도 있어 만석·합체 불가·스폰 고갈 교착에 구조 장치가 있다 (`:1510-1556`, `:1656-1669`, `:2368-2381`).
- `교체` 버튼은 주문을 바꾸는 선택이지 채점 확인 버튼이 아니며, 물리·등확률 은유 충돌도 없다.

## 우선순위 수정 백로그

심각도 내에서 수정 난이도가 낮은 순(`S → M → L`)으로 정렬했다. 같은 등급·난이도에서는 학습 오개념과 반복 노출 범위를 우선했다.

| 순위 | 게임 | 항목 | 심각도 | 난이도 |
|---:|---|---|:---:|:---:|
| 1 | 소수 스매시 | 온보딩의 ‘오답 방울은 목숨 유지’와 실제 목숨 차감 불일치 | 높음 | S |
| 2 | 소수 스매시 | ‘자연수를 곱하면 무조건 커진다’는 거짓 일반화 | 높음 | S |
| 3 | 대칭 브레이커 | 모든 주요 정답 경로의 화면 흔들림 | 높음 | S |
| 4 | 젤리 게이트 | 최적 선택·벽 통과 정답 경로의 화면 흔들림 | 높음 | S |
| 5 | 어림 대시 | 일반·경계 정답 통과의 화면 흔들림 | 높음 | S |
| 6 | 네모공장 | 치수 및 길이 합 답의 `cm` 단위 누락 | 높음 | S |
| 7 | 소수 스매시 | 임의 소수 곱셈을 이동·12초 압박 중 계산 | 높음 | M |
