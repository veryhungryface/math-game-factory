# 타이틀 로고 서체 다양화 배정표

> 대상: 카탈로그 24작 전부
> 상위 규격: `docs/title-screen-spec.md` (레이아웃·정보 위계·CTA 규격은 **불변**)
> 1단계 파일럿: 꽝도장 · 폴짝이 · 등불을 켜 (2026-08-29 적용 완료)

## 0. 왜 하는가 — 진단

8/20 타이틀 다양화에서 레이아웃 원형 6종을 배분했는데도 사용자 평가는
**"아직도 표지 제목 폰트가 똑같고 천편일률"** 이었다. 실측해 보니 원인이 명확하다.

`docs/title-screen-spec.md` §2.2 「복붙용 CSS」 레시피가 이렇게 되어 있다.

```css
font-family: "Black Han Sans", "Noto Sans KR", "Apple SD Gothic Neo", sans-serif;
```

그런데 **Black Han Sans 도 Noto Sans KR 도 저장소에 없다.** 웹폰트를 아무도
싣지 않았으므로 전 게임이 조용히 세 번째 후보인 시스템 폰트로 폴백한다.
결과적으로 코드 렌더 로고를 쓰는 9작이 **완전히 같은 글자꼴**(macOS 기준
Apple SD Gothic Neo Heavy)로, 같은 세로 그라디언트·같은 4px 외곽선·같은
8px 아래 압출로 렌더된다. 색만 다를 뿐 자소의 골격이 동일하니 다 똑같아 보인다.

이 문서는 폰트 8종 × 로고 처리 12종을 24작에 **같은 조합이 두 번 나오지 않도록**
배정한다.

```

F2 T8  T6  T4     F6 T9  T6  T12
F3 T7  T12 T11    F7 T10 T1  T7
F4 T4  T2  T3     F8 T8  T5  T12
```

## 4. 불변 규칙 (배정과 무관하게 지킨다)

1. **로고 대비 4.5:1.** 글자면이 배경과 붙으면 색을 바꾸기 전에 외곽선을 먼저 굵힌다.
2. **초등 5~6학년이 1초 안에 읽어야 한다.** 거친 손글씨·붓 계열(F6·F7)은 음절 수가 많을수록
   글자를 더 키우고 장식 그림자를 줄여라. 실측 사고 사례는 §6.
3. **본문·UI·HUD 는 시스템 폰트 스택을 유지한다.** 웹폰트는 **타이틀 로고와 부제(태그라인)까지만**.
   플레이 화면에 웹폰트를 끌고 들어가지 마라 — 서브셋에 그 글자들이 없어서 폴백이 섞인다.
4. `docs/title-screen-spec.md` 의 레이아웃·정보 위계·CTA 규격·금지 목록은 그대로다.
   로고 존의 좌표와 CTA 68px 규격을 서체 때문에 흔들지 않는다.
5. 등장 모션도 처리에 맞춰 바꾼다. 전 게임이 「위에서 낙하 + 오버슈트」인 것도 천편일률의 일부다.
   각인은 찍히고, 점프는 뛰어오르고, 등불은 켜진다.

## 6. 파일럿에서 실측한 함정

- **거친 붓 계열은 작게 쓰면 못 읽는다.** East Sea Dokdo 는 자폭이 약 `0.57em` 로 매우 좁아,
  기존 고딕과 같은 `font-size` 로 두면 실제 글자가 절반 크기로 보인다. 서체를 바꿀 때는
  `font-size` 를 그대로 두지 말고 **로고 본문 폭 330–358px(390 화면)** 를 다시 맞춰라.
- **명조는 속공간이 좁다.** Nanum Myeongjo EB 에 `-webkit-text-stroke` 를 5px 이상 주면
  `ㅇ`·`ㅁ` 안이 메워져 글자가 주황 덩어리가 된다. 먹선은 3px 안팎으로 묶고 판독은
  바깥 림과 글로우로 확보해라. 8방향 하드 그림자로 테를 두르는 방식은 명조에서 **금지**다.
- **`--y` 오프셋은 px 가 아니라 em 으로 줘라.** 390 에서 맞춘 ±14px 이 1280 에서는
  글자 크기 대비 과해져 글자끼리 부딪친다. 파일럿(폴짝이)에서 실제로 겹쳤다.
- **`animation-fill-mode:both` + `to{transform:none}` 조합 주의.** 끝 키프레임에서 transform 을
  명시하면 `nth-child` 로 준 정적 transform 을 덮어쓴다. 끝에는 `opacity` 만 두면 된다.
- **서브셋 글자 목록에 부제·공백을 빠뜨리지 마라.** 빠진 글자만 시스템 폰트로 렌더되어
  한 문장 안에서 서체가 섞인다.

## 7. 2단계(나머지 텍스트 로고 6작)에서 실측한 함정

- **`background-clip:text` 위에 어두운 하드 `text-shadow` 를 얹으면 글자 면이 통째로 먹는다.**
  배경은 배경 레이어에서 그려지고 text-shadow 는 그 위에 글리프 모양 그대로 찍히므로,
  `-4px 0 0 <어두운색>` 한 겹만으로도 면적의 90%가 가려져 글자가 검게 보인다(경계폭주에서 실측).
  텍스처·그라디언트 면을 쓸 거면 **글자 그림자는 쓰지 말고** 부모에 `filter:drop-shadow()` 로 줘라.
- **음수 `z-index` 의사요소는 부모의 배경보다 위에 그려진다.** CSS 페인트 순서가
  `요소 배경 → 음수 z-index 자식 → … → 인라인 텍스트` 라서, `::before{z-index:-1}` 로 깐 바깥 테는
  `background-clip:text` 로 만든 면을 덮어 버린다(유리를 불어에서 실측). **이중 외곽선(T8)처럼
  글자 뒤에 레이어를 깔 때는 면을 `color:` 로 칠해라** — `color` 는 텍스트 단계라 의사요소보다 위다.
- **T9 텍스처 클리핑은 면이 어두워야 산다.** 밝은 하늘 키 아트 위에서 밝은 물빛 텍스처를 넣으면
  배경과 붙는다. 텍스처 그라디언트를 아래로 갈수록 어둡게 잡고 먹선을 4px 이상으로 두면
  글자 윤곽이 배경 대비 5:1 이상 나온다(파도 검문소).
- **처리별 등장 모션 대응** — 각인은 찍히고, 점프는 뛰고, 슬랜트는 오른쪽에서 가로로 늘어난 채
  날아와 급감속하고(T10), 계단은 위 칸에서 한 칸씩 내려와 물리고(T11), 겹침은 좌우 바깥에서
  미끄러져 들어와 서로 물리고(T12), 텍스처는 `clip-path:inset()` 으로 아래에서 차오른다(T9).
  T9 의 마지막 키프레임 `clip-path` 는 **음수 inset** 으로 둬야 획이 잘리지 않는다.
