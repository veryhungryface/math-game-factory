# 몫 블록 — 빌드 검증 (2026-09-06)

구현: `public/g/quotient-blocks/index.html`, `engine.mjs`, `meta.json`.
6주문, 쟁반 손잡이 직접 드래그, 십의 자리 나머지 직접 내림, 회전 없는
[십의 몫, 일의 몫, 나머지] 조각 배치, 10×10 판의 가로줄 삭제를 구현했다.
오답은 핀 하나와 2×2 폐기 조각을 남기며 같은 자리로 돌아와 다시 계산한다.
핀 0 / 배치 불가능 / 시간 0은 실패다. 두 줄 삭제는 400점과 핀 하나 회복이다.

## 브라우저 검증 차단 — 게시 가능한 상태로 판정하지 않음

`node factory/lib/qa.mjs quotient-blocks`를 실행했다. 첫 실행에서 외부 모듈에 있던 훅이
정적 검사에 잡히지 않아 인라인 모듈로 수정했다. 재실행은 `serveStatic`에서
`listen EPERM: operation not permitted 127.0.0.1`로 중단됐다.
`FIRSTPLAY_PLAY_MS=45000 node factory/lib/firstplay/harness.mjs quotient-blocks`도 같은 오류로 중단됐다.
이 세션은 승인 요청이 금지된 workspace-write 샌드박스다. 포트 차단 우회나 게이트 수정은 하지 않았다.

실제 브라우저 pointer 이벤트, 픽셀 육안 검사, 네트워크 런타임 검사, FPS, 첫 플레이 프레임은
**미검증**이다. 모의 어댑터의 렌더 성공은 스크린샷 또는 input.real 통과를 뜻하지 않는다.
`meta.qa`는 요청대로 score 0 / passed false로 유지한다. 위 두 명령의 정상 완료가 다음 단계다.

## 기획서의 충돌·남은 확인

- 최종 심사 범위인 6주문·가로줄만 삭제를 우선했다. 원안의 세로줄 삭제, 9주문,
  회전, 별도 오류수정 밴드, 다중 모드는 포함하지 않았다. 직접 쟁반 만들기가 open_construct 조작이다.
- 명시된 첫 문제 60÷3은 내림 없는 예외 워밍업이다. 그 뒤 다섯 문제는 반드시 내림이 있다.
- 2문제인 각 밴드에서 눈금 비중 20% 이하는 불가능하다. 대신 본 주문 다섯 개의
  십의 몫을 0~4에서 각각 한 번씩 층화한다. 정답 쟁반 위치/예상 조각 외곽을 미리 공개하지 않는다.
- 제공된 title.png/rotor만 사용했다. 별도 생성 로고/CTA/PC 배경 파일은 없어서
  타이틀 로고는 코드 음각, CTA는 기존 생성 rotor와 코드 글자를 결합했다.
  생성 로고를 요구하는 사용자 규격은 아직 충족하지 못한 항목이다.
