## 구현 범위

- Canvas 2D 유백 아크릴 작업대에서 표시된 꼭짓점부터 다른 꼭짓점까지 직접 드래그한다. 이웃하지 않은 점이면 대각선이 끼워지고, 변·잘못된 도형·시간 초과는 목숨과 콤보를 잃는다. 하단 답 버튼이나 키보드 답 경로는 없다.
- 고정 정사각형 연습은 실제 드래그 전까지 시간·낙하를 멈춘다. 성공 시 두 끝점을 같은 모양과 색으로 1초 강조하고 이웃점은 어둡게 한다. 첫 밀기 판도 실제 면 스와이프까지 멈춘다. 완료 후 `onboardingSeen:star-out`을 저장하며 재방문은 본판부터 시작하고, 타이틀 도움말로 연습을 다시 열 수 있다.
- 본판은 정사각형·정오각형·정육각형, 곡선이 섞인 닫힌 도형, 모든 변은 같지만 각이 다른 오각형, 삼각형, 이미 대각선 하나가 끼워진 역추적 판을 순서 난도 덱으로 공급한다. 경과 30초·60초 또는 진행 밴드에 따라 낙하 시간이 8→6→4초로 바뀐다.
- 밀어내기는 판별 정답이지만 잠근 장수·콤보·점수에 포함하지 않는다. 맞게 민 판은 스와이프 방향으로 작업대 밖으로 빠진다. 일반 오답 뒤에도 같은 판을 다시 풀 수 있고, 첫 일반 실수 뒤 8장 잠금이 가능한 경로를 행동 검사로 확인했다.
- 3연속 잠금 뒤에만 `star_bonus` 판을 기존 순서에 삽입한다. 한 꼭짓점의 대각선을 잠근 뒤 0.8초 동안 나머지 세 대각선을 개별 또는 연속 끝점 드래그로 모두 공급하면 오각별·안쪽 오각형과 +300점이 열린다. 일반 오각형에서는 추가 별 입력이 거부된다.
- 목숨 0은 즉시 terminal phase가 되며 자동 복구하지 않는다. 결과지를 0.8초 늦춰 그 사이 현재 판의 실금과 라이트테이블 소등을 보인다. 낙하 실패 판도 0.85초 치우기 전까지 실패 문구가 다음 판 안내에 덮이지 않는다. 결과 점수는 결과지가 보인 뒤 0부터 센다.
- 손맛은 65~75ms 안착 정지, 판 압축/복원, 납선 폭 안착, 정답 유리색 플래시, 드래그 잔상, 느린 유리 반사, WebAudio 동기화로 구현했다. 파티클·점수 팝업·정답 화면 흔들림은 사용하지 않는다. 무효 조작은 대상 판만 흔들고 리플·올바른 대상 방향·이유 문장을 함께 보인다.
- 390×844 세로판과 1280px 극장형 와이드판, 44px 이상 조작부, 음소거, `prefers-reduced-motion`, 상대 에셋과 `img.onerror` 폴백, RAF+delta time을 구현했다. 판·선·기록 배열은 세션 크기로 제한된다.

## B3 무뇌 봇 — 각 200게임

`bots-vm.json`은 바뀌지 않은 HTML 스크립트를 최소 DOM/Canvas Node VM에서 실행하고 등록된 포인터 핸들러에 좌표를 넣는다. 안내 2종은 공통 훈련으로 끝내고 일반 `firstAttempts`에서 제외한다. 정책은 보이는 꼭짓점·표시점·이미 끼운 선만 받고 `kind`, 정답, 내부 판정 함수는 받지 않는다.

| 정책 | 첫 시도 정답률 | 정책별 우연 수준 | z | 완주율 |
|---|---:|---:|---:|---:|
| 동일 끝점 연타 | 46/271 = 16.974% | 24.600% | -3.100 | 0/200 |
| 둘레 순서 순환 | 0/600 = 0% | 0% | 0 | 0/200 |
| 무작위 꼭짓점 순열 | 123/557 = 22.083% | 21.394% | 0.408 | 0/200 |
| 무입력 | 0/600 = 0% | 0% | 0 | 0/200 |

연타는 한 선이면 끝나는 본판 정사각형에 보수적으로 1/3 기회를 두고, 여러 선·버리기 판은 0으로 계산했다. 무작위는 각 도달 판마다 `1 / C(n-1-pre, n-3-pre)`, 버리기 판은 0을 가중했다. 무작위 실측은 기대보다 0.689%p 높지만 z=0.408로 유의한 초과가 아니다. 시드나 표본을 결과에 맞춰 바꾸지 않았으며, “숫자 그대로 모두 우연값 이하”라고 과장하지 않는다. 네 정책 모두 완주 0이고 무입력 진도도 0이다.

`bots-browser.mjs`도 별도로 추가했다. 이 하네스는 Canvas 픽셀에서 꼭짓점과 인두를 찾고 공개 상태의 phase/token/history만 읽으며, 답 입력은 `page.mouse`의 trusted 이벤트만 사용한다. `answerCorrect`, `answerWrong`, `simulateInput`, `dispatchEvent`를 금지하고 trusted/untrusted 포인터를 분리 계수한다. 구문 검사와 `--self-check`는 통과했지만 이 환경에서는 아래와 같은 포트 제한으로 800판을 실행하지 못해 `bots-browser.json`은 `status: blocked`다.

## 실행되지 못한 브라우저 검사

다음 요구 명령을 그대로 실행했다.

```sh
node factory/lib/qa.mjs star-out
FIRSTPLAY_PLAY_MS=45000 node factory/lib/firstplay/harness.mjs star-out
B3_RUNS=200 B3_CONCURRENCY=8 node logs/star-out-build/bots-browser.mjs
```

세 명령 모두 로컬 서버 단계에서 `listen EPERM: operation not permitted 127.0.0.1`로 종료했다. 게임을 연 뒤 생긴 예외가 아니라 브라우저 이전의 실행 환경 오류다. 서버 없는 `file://` Puppeteer 탐침도 Chrome 프로세스 시작이 막혔다. 권한 우회나 QA 게이트 수정은 하지 않았다.

따라서 **공식 QA 치명 0건, 실제 trusted 터치, 콘솔/404 0건, 390px 실제 렌더, 첫 플레이 프레임, FPS·15초 유지율은 미검증**이다. 브라우저가 허용된 호스트에서 위 세 명령을 다시 실행해야 한다. 게시·허브 빌드·큐 장부·`meta.qa`는 변경하지 않았다.
