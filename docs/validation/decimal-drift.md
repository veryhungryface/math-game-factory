# 소수 드리프트 검증

대상: `public/g/decimal-drift/`, 4학년 2학기 3단원 소수의 덧셈과 뺄셈.
성취기준: [4수01-14], [4수01-16].

## 설계와 실제 입력

두 갈림길에서 각각 세 길 중 하나를 골라 출발 연료에 충전량을 더하거나 사용량을 뺀다. 9가지 경로 중 도착 연료가 다리 목표와 일치하는 경로는 정확히 하나다. 계획 중에는 시간이 흐르지 않고, 계산 결과를 미리 공개하지 않는다. 출발 후 연료 표지와 현재 연료가 갱신되고 일치할 때만 다리 차단기가 열린다. 이동 중 좌우 버튼/방향키로 실뭉치를 수집하면 추가 점수를 얻는다. 세 코스의 아홉 다리를 열면 완주한다. 잘못 선택하면 실제 계산식과 목표와의 차이를 확인하고 같은 구간을 다시 고를 수 있으며, 수리 기회 세 번을 모두 쓰면 종료한다.

`node scratchpad/decimal-drift/verify.mjs`에서 게임 시작 버튼, 3단계 도움말, 경로 버튼과 출발 버튼을 실제 클릭하고 방향키를 실제 입력했다. `answerCorrect()`나 `answerWrong()`를 사용하지 않고 아홉 다리 완주, 오답 3회 종료, 재시작 초기화를 확인했다. `solutionHint()`는 경로 데이터만 읽는 함수이며 입력이나 점수를 조작하지 않는다.

- 실제 완주: 9/9 다리, 수리 3/3, 종료 `won`.
- 실제 실패: 수리 2 → 1 → 0, 해결 수 0 유지, 종료 `lost`.
- 다시 달리기: 점수 0, 수리 3, 첫 구간, 두 경로 미선택.
- 뷰포트 360×800 / 390×844 / 820×1180 / 1280×800: 가로 넘침 없음, 표시된 모든 버튼 44px 이상.
- 캡처: `scratchpad/decimal-drift/{planned-mobile,drive-mobile,bridge-success,win-mobile,pit-mobile,lost-mobile}.png`.

## 수학 검산

소수는 전부 100분의 1 단위 정수로 저장하며 판정은 정수 동등 비교만 사용한다. 출력 시 끝자리 0을 제거하므로 1.90과 1.9를 같은 수로 다룬다. 최초 코스는 소수 첫째 자리, 둘째 코스는 두 자리 덧셈과 뺄셈, 마지막 코스는 사용 후 충전과 충전 후 사용을 섞는다.

5000개 문제 × 9개 모든 경로 = 45000개 경로를 열거 검산했다. 정수가 아닌 값, 음수 결과, 중복 경로 결과, 정답 부재, 복수 정답, 정답 경로와 목표 불일치 모두 0건. 서로 다른 발문 5000개. 끝자리 0을 포함하는 목표 489개. 결과는 `scratchpad/decimal-drift/verification.json`에 저장했다.

## 미술 및 자산

새 캐릭터나 상용 게임 자산을 복제하지 않았다. 캐릭터는 공용 자눈 캐스트 상대 경로 사용. 자체 Canvas 도로, 곡선 코스, 나무, 섬, 등대, 실타래와 깃발, 차량, 연료 표지, 열리는 차단기를 구현했다. 시작 화면은 별도 생성 이미지 `assets/backdrop.png`를 사용한다. 사용자 제스처 이전 오디오 없음, 음소거 버튼 제공. 게임 소유 범위를 벗어난 공유 파일 변경 없음.

자동 QA와 최종 네트워크 검증은 생성 배경 수령 뒤 기록한다. 아래 수치는 이미지 생성 대기 중의 첫 실입력 검증이며, 당시 유일한 404는 아직 존재하지 않던 `assets/backdrop.png`였다.


## 최종 아트 / QA

생성 원화 1536×1024를 수령하여 모바일 390×844, 가로 표지 1200×630, 정사각 표지 1080×1080을 실제 브라우저로 다시 캡처하고 육안 확인했다. 썸네일은 배경·로고·시작 버튼이 분리되어 읽히며, 모바일에는 곡선 트랙과 카트가 남는다.

`node factory/lib/qa.mjs decimal-drift --out scratchpad/decimal-drift/qa`: 41/43 통과, 치명적 결함 0, 콘솔 오류 0, 실패 요청 0. 미통과 2건은 병렬 브라우저 측정 중 FPS: 모바일 원시 중앙값 29 / 데스크톱 27, 동일 머신 벤치 3fps, 보정 116/108fps로 하네스가 비치명 머신 부하 경고를 기록했다. 이 수치만으로 실제 주행 성능을 통과라 주장하지 않는다. 정지 계획 화면 캐시는 자연스럽게 움직이지 않는 계획 상태에만 적용되고 주행은 매 프레임 그린다. 별도 `renderStats()`로 실제 Canvas 렌더 프레임과 경과 시간을 읽을 수 있다. 호스트가 브라우저를 직렬화해 최종 실제 주행 측정을 이어간다.

갈림길 수정: 선택한 왼쪽/가운데/오른쪽 위치에 연료 표지가 놓이며, 첫·둘째 갈림길 각각에서 카트가 그 차선으로 이동한다. 이 짧은 구간에는 '고른 길로 달려요' 안내와 비활성 조향 버튼을 보이고, 구간 사이에는 수동 드리프트를 할 수 있다. 조향 입력과 자동 안내가 서로 싸우지 않는다. 순위가 동적으로 계산되지 않으므로 결과에서 탁 반장보다 앞섰다고 주장하지 않는다.

## 직렬 실제 주행 성능 수정 및 통과

호스트의 단독 브라우저 재측정에서 기존 데스크톱 주행이 19.4fps로 느린 것이 확인되어 수정했다. 세계 Canvas의 실제 버퍼만 최대 240000픽셀로 제한하고, 논리 좌표와 DOM 수학·버튼은 원래 해상도로 유지했다. 도로 조각을 44개에서 32개로 줄이고, 속도계 숫자가 같을 때에는 DOM을 다시 쓰지 않는다. 미술의 질감을 유지하면서 실제 주행 비용을 낮춘 수정이다.

다른 작업 브라우저를 모두 닫은 상태에서 `node scratchpad/decimal-drift/perf-forks.mjs`로 실제 5.3초 주행을 측정했다. 결과: 390×844 **30.75fps**, 1280×800 **35.95fps**. 첫 길 왼쪽과 둘째 길 오른쪽 선택이 두 화면 모두에서 실제 카트 위치 x<−0.6 / x>0.6으로 확인되었다. 결과 파일 `scratchpad/decimal-drift/perf-forks.json`. 이 검사는 정지 계획 화면의 캐시 프레임을 세는 검사가 아니라 출발 버튼을 실제 클릭한 뒤 주행 중에만 측정했다.
