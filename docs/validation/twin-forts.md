# 쌍둥이 요새 검증 기록

- 사용자 요청: Supercell 게임 조사·벤치마크 후 실제 오리지널 게임 제작. 이미지 생성과 Blender 에셋 제작 포함.
- 게임: `public/g/twin-forts/`, 6학년 2학기 4단원 비례식과 비례배분, `[6수02-05]`.
- 제작 범위: 병력 N명을 a:b로 직접 배치하는 싱글플레이 3D 게임. 1회 안내 + 일반 8문항, 총 9작전. 계산 중 시간 제한 없음. 출격 뒤 약 3초 진격·포격·요새 붕괴. 세 번 오답이면 원정 실패. 승리 깃발/최고 기록은 같은 브라우저에 저장.
- 연구: [공식 자료 기반 벤치마크](../../references/case-studies/supercell-benchmark-20260907.md). 원작 앱 실플레이 및 어린이 사용자 조사는 수행하지 않았다.
- 에셋: Blender 5.2.1 원본 모델 7종(병사 2종·요새·기지·나무·바위·깃발)을 실제 WebGL 장면에 사용. 생성 원화·Blender 렌더 표지 포함. `assets/twin-forts-source.zip`에 원본 `.blend`, 생성 스크립트, GLB, 프롬프트·제작 기록 제공. 공용 vendor 수정 없음.

## 증거와 재현

`logs/manual-20260907-twin-forts/`에 호스트 실화면, 공식 QA, 순진한 첫플레이, 독립 정수 검산과 실입력 검증, 리뷰를 보존한다. `artifact-manifest.json`은 meta.json을 제외한 모든 게임 파일의 해시를 연결한다. meta.json은 게시기가 qa 상태를 갱신하므로 공개 배포 시 별도로 대조한다.

- 호스트 실입력: 390×844, 320×720, 820×1180, 1280×800, DPR 2. 시작과 1명 이동 버튼 3회로 안내 30명을 12/18명으로 배분한 뒤 출격 성공. 가로 넘침·실행 오류·실패 요청 없음.
- 최초 QA가 index.html의 문자열만 검사해 외부 game.js의 실제 훅을 놓쳤다. 테스트 객체를 모듈에서 export하고 index.html에서 window에 노출하는 방식으로 정리했다. `qa-initial-static-module/`에 원래 실패 보존.
- 다음 QA의 범용 실입력 탐색이 홈 링크를 게임 조작으로 오인해 페이지를 떠났다. 홈 링크의 의미를 `back-link` 클래스와 돌아가기 접근성 이름으로 명시해 하네스의 크롬 제외 규칙과 일치시켰다. `qa-initial-navigation/`에 원래 실패 보존. 판정 함수·수학 로직·디자인에는 영향 없음.

## 검증의 한계

호스트 Chrome의 실제 GPU에서 모바일 뷰포트를 사용한다. 실제 휴대전화 하드웨어 성능 측정이나 어린이 사용자 조사는 아니다. 독립 오라클로 답을 알고 실행한 완주 검증과 답을 모르는 첫플레이/정책 검증은 구분한다. 멀티플레이·클랜·카드 수집 기능은 이번 게임에 포함되지 않는다.

## 최종 공식 QA

44/44 통과, 치명적 결함 0. ANGLE/Metal Apple M4 실제 GPU, 모바일 뷰포트 중앙값 60FPS, 데스크톱 61FPS, 15초 후 유지율 100%. 콘솔·예외·실패 요청·가로 넘침 0. 실제 pointer 입력 응답 확인. 40/17/63개 표본 호출을 각각 존중하고 합집합 112문항, 핵심 문장 다양성 100%.

재현: `node factory/lib/qa.mjs twin-forts --out logs/manual-20260907-twin-forts/qa`.

## 독립 수학 검산

개발 담당과 다른 검산 담당이 BigInt 오라클로 전체 596문항과 안내 문항, 정수 배분 33,341상태를 대조했다. 실제 campaign 함수 5,000회·일반 40,000문항, 최종 QA 한국어 발문 112개를 별도로 파싱해 재계산했으며 오류 0, verdict pass다. 실제 플레이와 QA 샘플이 동일한 math.mjs 풀을 사용한다.

좌우 반전·같은 비·약분하지 않은 비·0명/전원 배분·범위 밖 및 비정수 입력을 포함한다. 출제 총원은 12~90명이며 각 항은 1~9다. 안내 첫 문항은 일반 첫 시도 정답률에 포함하지 않는다. 무뇌 정책의 기준은 실제 일반 출제 분포에 따로 계산한다. 반반 배분의 기대 정답률 약 11%와 임의 정수 배분 약 2.78%를 같은 기준으로 혼동하지 않는다.

원본 에셋 ZIP은 CRC 검사를 통과했고 들어 있는 GLB 7개가 공개 게임에 사용한 파일과 바이트 단위로 일치한다. source-pack-check.json에 기록했다.

## 첫 플레이에서 발견한 오답 재배치 수리

수리 전 순진한 첫 플레이 15프레임에서 29~51초 동안 오답 결과 화면에 머물렀다. 손잡이를 가리키는 안내는 남았지만 입력은 잠겨 있었고, 별도의 '배치 고치기' 버튼을 먼저 눌러야 했다. 독립 검수는 이를 high로 기록하고 통과를 보류했다. 수리 전 QA와 첫플레이는 `qa-before-retry-fix`, `firstplay-naive-before-retry-fix`, 독립 재현은 `validation/revision-1`에 보존한다.

이제 오답 결과 화면에서도 손잡이와 1명 이동 버튼이 활성화된다. 처음 드래그하거나 버튼/방향키를 누르면 같은 문항의 병력을 바로 다시 배치한다. 전투 중에는 손잡이 안내를 숨기고, 오답 뒤에는 활성 손잡이에만 안내를 표시한다. 기존 '배치 고치기' 경로도 유지한다. 시도·목숨·첫 시도 기록은 초기화하지 않는다.

## 전장을 직접 누르는 첫 플레이 보완

독립 재검수에서 전장 드래그/탭은 병력 배치 입력이 아닌데 아무 반응도 주지 않는 점을 지적했다. 최종 수리에서는 접점에 짧은 원형 반응을 표시하고, 실제 손잡이 안내를 재노출한다. 휴대폰은 '아래 손잡이', 와이드는 '오른쪽 손잡이'로 위치를 알려 준다. 단일 DOM을 재사용해 흔적이 누적되지 않는다. 이 안내는 배분·정답 판정·시도·첫 시도 기록을 바꾸지 않는다.

`hint/report.json`과 4개 캡처에서 390/1280px 실제 전장 탭 반응, 오답 해설 보존, 바로 이어지는 정밀 조작→정답 출격 성공을 확인했다. 390px에서 playing 진입 뒤 8초 무입력도 완료·시도 0과 초기 배분을 유지했다. 첫 플레이 수리 전/후 순진한 입력 시퀀스는 별도 폴더로 보존한다.
