# 쌍둥이 요새 독립 검증 계획

상태: 빌드 대기. 브라우저는 호스트 허가 전 시작하지 않음. 게임 코드는 수정하지 않음.

## 독립 계산과 데이터 연결

- `oracle.mjs`는 생산 코드 import 없이 BigInt로 `N×a/(a+b)`, `N-left`, `left×b=right×a` 계산.
- 정수 해 조건은 분자 나눗셈의 나머지0. 약분 전 비에서 `N%(a+b)===0`은 필요조건이 아님(15명을2:4→5/10).
- 실제 공개 풀 전수, 실제 makeCampaign 다수 호출, sampleProblems(40/17/63) 모두 같은 오라클 대조.
- 캠페인 데이터와 샘플이 정말 같은 생성기/풀에서 나오는지 소스 추적 + 각 행의 (N,a,b) 키 멤버십 비교.
- 좌우 순서 뒤바뀜, 약분되지 않은 비, 같은 비, 전항 큰/작은 사례를 따로 집계. 실제 화면의 '왼쪽:오른쪽'과 a:b 대응을 캡처.
- 판정 함수를 각 문항의 모든 정수 left=0..N에 대해 비교. 가능한 입력 중 정확히 한 해, 소수/범위 밖/NaN 거부 확인.
- meta g6s2-u4 및 [6수02-04]/[6수02-05] 원문 내용 확인. 비례배분 중심이므로 [6수02-05]가 직접 근거.

## 무뇌 정책

- 튜토리얼 고정30명2:3은 일반 통계에서 제외.
- 반반, 고정왼쪽12/20명, 고정40%, 양 끝, 반복쓸기 후 제출, 무작위 정수0..N, 무입력.
- 각 정책의 우연baseline은 실제 일반 캠페인 분포에서 그 좌표가 해인 비율. 무작위는 평균1/(N+1). 전역0.1%같은 가짜 baseline을 쓰지 않음.
- 무입력은 첫시도 정확도 정의불가, 진도0인지 측정. 홀드/연타는 자동스냅·정답하이라이트·비율고정 유지로 정답률이 올라가는지 확인.
- 소스 오라클 평가와 실제 UI 실행 결과를 분리해 기록. 봇 완주율을 학습 성과 기준으로 쓰지 않음.

## 실제 UI 및 게임성

- 모바일390×844 실제 터치 드래그/정밀버튼, 데스크톱 키보드/마우스로 한 판씩.
- 정상9라운드 완주(조작은 UI), 일반1실수 뒤 같은 문제 수정하여9라운드 완주, 일반실수3번 실패 및 재시작.
- 승리 후 localStorage 성장/기록 보존, 재로딩 후 실제 모델/장식 변화. 저장차단 시 크래시 없는지.
- 배치 전 총원/좌우량 맞음, 조작 중 실제 병력 재배치, 배치 후 전투 인과, 오답 설명의 실제 값 확인.
- 처음 보는 타이틀→시작→첫조작→첫성공 시퀀스. 목표·조작·비례배분 쓰임이 화면만으로 명확한지.
- 학습자 테스트로 오인하지 않도록 자동입력 탐침과 규칙을 익힌 평가자의 2회차를 구별.
- 반복 플레이 의향은 전투변화·배치판단·성장 보상 실제 행동 근거로 평가; 효과 개수로만 재미점수 주지 않음.
