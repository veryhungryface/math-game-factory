# 두 3D 게임의 디자인 세부 보정

사용자 원문: “음 이런 3d스타일 마음에 들어. 조금만 더 디자인이 섬세하면 더 만족스러울것 같아. 조금만더 신경써줘봐. 두 게임 모두”

대상은 쌍둥이 요새 `twin-forts` v2→v3, 햇살 바구니 `sunbasket-farm` v1→v2다. 마음에 든 3D 미니어처 스타일과 게임 구조를 유지하며 실제 플레이에서 보이는 완성도를 높인다. 새 게임이나 광범위한 재설계는 요청하지 않았다.

## 방향

- 요새: 돌과 나무의 면·모서리·이음매를 섬세하게, 수로에 둑 가장자리/잔물결, 큰 단색 지형에 풀 군락·마모 흔적을 적절히 배치. 반복 대칭의 큰 읽힘은 유지하되 작은 디테일만 변화시킨다. 병력과 경로가 시각적으로 묻히면 실패다.
- 농장: 원뿔처럼 보이는 반복 풀을 작은 잎과 꽃 군락으로, 흙길 가장자리와 건물 주위의 접지를 자연스럽게. 창틀·화분·처마/어닝·판매대 주변 세부가 실제 모바일에서 보이게 한다. 더 부드러운 빛/그림자와 풍성한 과수 형태. 밭/치수/수확 동작 영역은 비운다.
- 양쪽 모두 화면 전체의 채도·밝기·재질을 조율하고 UI 테두리/간격/숫자 위계를 세밀하게 다듬는다. HUD를 키우거나 설명/글씨를 작게 만들어 디테일 공간을 확보하지 않는다.

## 경계와 증거

수학 모듈, 문제 생성 분포, 정답 판정, 점수·첫 시도·목숨·저장 상태를 보존한다. 시각/카메라를 바꾸면 실제 좌표 조작과 최대 개체 수를 검증한다. 모델 자체가 바뀌면 같은 GLB·Blender 원본 ZIP·표지를 함께 갱신하고 CRC/바이트 일치를 확인한다. 런타임 장식으로 구현하면 해당 코드도 원본 다운로드에 포함할 수 있으나 원본 GLB를 다시 만들었다고 주장하지 않는다.

중간 meta.qa의 passed/score는 건드리지 않는다(다른 허브 빌드가 기존 게임을 숨기는 사고 방지). 최종 검수 뒤 부모가 publish-game.mjs로 재게시한다. 수정된 파일 참조에는 새 버전 캐시 키를 넣는다. vendor/curriculum/자동 생성 허브 직접 편집 금지. 커밋·배포·HANDOVER·공통 검수 스크립트는 부모 소유.

코드/Blender 제작은 게임별 담당자만 해당 폴더를 편집한다. 브라우저/Blender GPU는 한 번에 한 담당자만 쓰고 부모에게 시작/반환을 알린다. GPU 없이 독립적으로 진행할 준비 작업은 병렬로 한다. 최종 실제390px 전후 비교와320/820/1280px 가독성·가림·입력, 공식 QA, 독립 수학 불변·최종 QA표본 재검산, 실제 플레이 회귀 후 검수 점수에 따라 게시한다. 기존 동일 수학의 대량 검산은 해시로 재사용한다.

최종 판정은 상용 동급이나 어린이 선호를 주장하지 않는다. 사용자가 확인하기 쉽게 실제 개선점과 두 공개 링크를 제공한다.
