## 이번 변경에서 확인할 것

1. 농가가 실제 390px에서 처마 두께, 지붕과 벽의 비율, 현관의 앞뒤 깊이로 이전과 구분되는가. 창 화분/못만 늘었으면 대표 형태 개선으로 쓰지 않는다.
2. 판매대 어닝의 늘어짐·가장자리와 지지대, 진열대 높이/상품 덩어리가 다른 각도에서도 읽히는가. 장식이 납품 수레를 가리면 개선으로 보지 않는다.
3. 사과나무의 큰/작은 수관이 비대칭이고 가지가 보이는 틈이 있는가. 회전만 바꾼 같은 공 모양을 서로 다른 변형으로 세지 않는다. 어린나무/성목/수확 후 상태가 실제 메시와 게임 렌더에서 어떻게 구분되는지 확인한다.
4. 당근의 새싹/성장/성숙이 잎 수·높이·뿌리로 구분되는가. 단순한 균일 확대만 있으면 그대로 적는다. 새 모델의 12개·144개 수확 화면에서 종류와 경계가 읽히는지 본다.
5. 기존 카메라/조명의 통제된 모델 전후 화면과 최종 실제 게임 화면을 나눠 본다. 새 조명/카메라 효과를 모델의 형태 개선으로 모두 돌리지 않는다.
6. 재사용 모델은 이름이 있는 부품·바닥 원점·크기 규칙·색 변경 범위를 확인한다. 같은 원본을 농장과 작은 시장의 다른 배치에 놓은 증거가 있어야 재사용이 검증됐다고 말한다. 새 GLB와 ZIP 안 GLB/원본의 바이트 일치도 확인한다.
7. 320/390/820/1280px에서 주문 숫자, 규칙, 밭 경계·치수·손잡이, 수확 좌표가 장식에 가리지 않아야 한다. 실제 입력 성공과 최대144개 렌더/수확, GPU 프레임률/15초 유지율을 별도 측정한다.

## 수학과 상태 검증

기존 math.mjs SHA는 `8d440d5b36d58d3146deaa4d155843bc25aebde60fe48adce121b35e87189dd8`다. 같은 SHA일 때만 이전 99문항+안내1, 3,400 판정, 5,000일/40,000 일반문항, 2,000표본 감사 결과를 재사용한다. 최종 QA의 실제 한국어 발문은 `상자 수 ÷ 가로`를 BigInt로 새로 계산하고, 1m²당1상자 규칙·답의 m 단위·메타 수치를 대조한다.

채점·목숨·첫 시도·총 시도·수확 중복·코인·진도·저장 관련 21개 함수와 저장 키를 기준 소스와 대조한다. 함수가 바뀌면 차이를 읽고 필요한 경로를 실제 입력으로 새로 검증한다. 이전 대량 감사나 9주문 완주를 다시 실행했다고 쓰지 않는다.

새 모델은 렌더링과 크기/클릭 범위에 영향을 주므로 수학이 같아도 실제 UI와 최대 개체 수 검증을 생략하지 않는다. 첫플레이 탐침에서 본 프레임과 그 유효 범위를 기록하며, 탐침이 안내 문항에 머물렀다면 그 사실을 숨기지 않는다.
