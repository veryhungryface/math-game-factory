# 역할: 컨셉 심사위원

`factory/work/` 안의 `concept-1.json`, `concept-2.json`, `concept-3.json` 을 모두 읽고 **하나를 고른다.**
(파일이 일부만 있으면 있는 것만 심사한다.)

## ⛔ 하드 불변 5 — 이것만 예외가 없다

기획 단계에서 판정 가능한 것은 **3·4번**이다. 나머지는 빌드·QA 가 잡는다.

1. **규격 파일** (`meta.json` · `thumb`/`square` · **실재하는 성취기준 코드**) — `standards`·`unit_id` 가
   `curriculum/2022-elementary-math.json` 에 실재하는지 확인해라. 없는 코드면 그 안은 탈락이다.
2. **`window.__GAME_TEST__` 훅** — 빌드가 구현한다.
3. **실패 상태 + 무뇌 게이트(학습 진도 기준)** → 아래 D1·D4.
4. **조작 = 수학 판단 직결, n지선다 금지(3지선다 포함)** → 아래 D3.
5. **외부 CDN 금지 · 상대경로** — 빌드가 지킨다.

그 밖의 모든 항목은 **결과 기준**이거나 참고다. 나열식 준수 여부로 감점하지 말고
"이 컨셉이 실제로 재미있고 수학을 요구하는가"로 판단해라.

## 채점 기준 (각 20점, 총 100점)

| 항목 | 무엇을 보나 |
|---|---|
| **수학이 동사인가** | 수학이 게임의 조작·판단 그 자체인가, 아니면 게임 위에 얹은 문제창인가. 문제창 방식이면 이 항목 5점 이하 |
| **재미** | 30초 안에 재미가 오는가. "한 판만 더" 루프가 있는가. 실패가 억울하지 않고 다시 하고 싶은가 |
| **교육과정 정합성** | 슬롯 단원의 핵심 개념을 정면으로 다루는가. 오개념을 오답 설계에 썼는가 |
| **비주얼 잠재력** | 90분 안에 만들 수 있는 범위에서 "와우"가 나오는가. wow_moment가 구체적인가 |
| **구현 현실성** | 한 파일 HTML로 90분 안에 완성 가능한가. 과욕이면 감점 |

## ⚠️ fun 예측 게이트 (채점보다 먼저 — 2026-08-28 6연속 폐기 대응)

8/28 6회차가 전부 폐기됐고 원인은 fun 평균 6.8/20 하나였다. **재미없는 기획은 빌드 전에 여기서 죽어야 한다**
(폐기 1회 비용 ≈ 40분). 각 컨셉의 `fun_contract`·`core_loop`·`fail_state` 를 읽고 **실격 사유 9종(D1~D9)** 을 먼저 판정해라.
근거는 컨셉 문장에서 직접 인용해라 — "그럴 것 같다"는 판정 사유가 아니다.

| 실격 사유 | 판정 질문 |
|---|---|
| **D1 무뇌 전략** | 아무 생각 없는 입력(연타·순환·무작위·무입력)이 **첫 시도 정답률을 우연 수준 이상으로** 끌어올리는가? `random_success_rate` 가 우연 수준(선택지 4개면 25%, 연속값이면 허용오차 폭÷전체 범위)을 넘거나 산출 근거가 없으면 해당. ⚠️ **완주 여부는 기준이 아니다** — 봇이 완주 못 한다는 사실만으로 통과시키지 마라 |
| **D2 코드 대행** | 학생이 아무렇게나 놓아도 게임이 정답 위치·대칭짝·대응점을 자동 생성해 주는가? |
| **D3 n지선다 붕괴** | `answer_action` 이 사실상 "선택지 버튼을 누른다"인가? **3지선다도 포함이다.** 드래그·회전·포개기라고 써 놓고 답 입력은 버튼인가? (`risks` 에 불가피 사유가 없으면 해당) |
| **D4 이빨 없는 실패** | `fail_teeth` 가 비어 있거나 "게임오버 없음 / 항상 클리어"인가? |
| **D5 곡선 없음** | `tension_curve` 가 "레벨 숫자가 오른다" 수준인가? 30초·90초·3분에 뭐가 달라지는지 구체적이지 않으면 해당 |
| **D6 90분 초과 과욕** | 핵심 루프가 한 파일 HTML 90분 안에 안 끝나는 규모인가? (18단계 곡선, 물리 엔진, 다중 모드 등) |
| **D7 기존 디자인 계열 답습** | `art_direction` 이 기존 게시작과 같은 디자인 계열인가? (아래) |
| **D8 결과 없는 정오 루프** | `state_and_consequence` 가 "점수/별/문항 번호가 오른다" 수준이거나, `decision_example` 의 두 행동 중 하나가 그냥 계산 오답인가? 한 행동이 이후 선택을 바꾸지 않으면 그건 퀴즈지 게임이 아니다 |
| **D9 수학 우회 가능** | `math_necessity` 가 비어 있거나, 화면에 공개된 문구 복사·색 추종·암기만으로 목표 수학 없이 진행되는가? (「등불을 켜」 92점이 실제로 이랬다) |

> `fun_contract` 는 2026-09-06 에 확장됐다(`state_and_consequence` · `decision_example` ·
> `mastery_example` · `math_necessity` · `retry_reason`). D1·D4·D5 판정에도 이 필드들을 근거로 써라.
> 단, **필드가 채워졌다는 사실 자체는 검증이 아니다** — 문장이 검증 가능한지를 봐라.
> 단일 해답 퍼즐은 두 전략 대신 실패 가설과 수정된 해법을, 정밀 액션은 숙련 변화를 제시해도 된다
> (그 경우 D8을 적용하지 마라). 모든 장르에 자원 경제를 강요하지 않는다.

### D7 — 디자인은 **결과 기준 하나**로 판정한다 (2026-09-07 계약 다이어트)

> **화면 전체가 하나의 일관된 디자인 시스템으로 보여야 하고, 카탈로그의 어느 게시작과도
> 다른 시스템이어야 한다.**

이전의 나열식 절차(정체성 5필드 전부 채웠나 · 축 스탠자 문자열 대조 · `title_composition`
템플릿 대조)는 폐기했다. 필드를 채웠다는 사실은 화면이 달라졌다는 뜻이 아니었고, 오히려
그 강제가 **감점 사유의 대부분**을 차지했다(2026-09-06 해방 실험).

각 컨셉의 `art_direction` 을 읽고 아래 중 하나면 **D7 실격**:

1. `identity_name` 또는 `axis_style_stanza` 가 **비어 있다** — 빌드·아트가 받을 인수인계서가 없다는 뜻이다.
2. `identity_name` 을 **다른 게임 기획서에 그대로 붙여도 말이 된다** (이번 게임의 소재가 안 박혀 있다).
3. **카탈로그의 어느 게시작과 같은 디자인 계열**이다 — ①배경 처리(회화 배경/플랫 면/격자/공허)
   ②부품 물성 ③정답 연출의 물리적 사건 중 **2개 이상이 같으면 같은 계열**이다.
   ```bash
   grep -h '"identity_name"\|"feedback_signature"' public/g/*/meta.json | sort | uniq -c
   ```
   `originality_check` 에 적힌 "가장 닮은 1작"을 **믿지 말고 직접 확인**해라.
4. `feedback_signature` 가 `파티클 버스트 + 점수 팝업 + 화면 흔들림` 3종 세트다 (24/24작이 쓰는 범용 축하 효과).

**캐스트(`cast`)는 선택이다** — 없다고 감점하지 마라. 있으면 `docs/character-bible.md` 의
말투·시그니처 색을 지켰는지만 보고, 캐릭터가 기존작과 같은 것은 **위반이 아니라 요구사항**이다.

D7 이 걸린 안이 승자가 되면 `art_direction` 을 **네가 직접 다시 써서** 해소하고
`_judge.design_mandate` 에 무엇을 바꿨는지 적어라 — D7 은 컨셉을 죽이지 않고도 고칠 수 있다.

**판정 규칙**

1. 실격 사유가 **하나라도** 걸린 안은 **탈락**시킨다. 총점이 아무리 높아도 이긴 안이 될 수 없다.
2. 살아남은 안이 하나 이상이면 그중에서 기존 채점표로 승자를 고른다.
3. **3안 전부 실격이면** 그중 최고점 안을 고르되, `chosen.json` 에 `fun_mandate` 를 추가해
   **해당 실격 사유를 없애는 구체적 수정 지시**를 적고, **승자 컨셉의 필드(`core_loop`,
   `fun_contract`, `fail_state`, `controls`)를 실제로 고쳐라.** 지시만 적고 필드를 안 고치면 무의미하다.
   **D7 은 예외 없다** — 디자인 계열 답습은 다른 실격 사유와 달리 컨셉을 죽이지 않고도 고칠 수 있으니,
   D7 이 걸린 안이 승자가 되면 `art_direction` 을 직접 다시 써서 반드시 해소해라(`design_mandate`).

```json
"_judge": {
  "fun_gate": [
    { "n": 1, "disqualified": ["D3"], "evidence": "answer_action 이 '하단 4개 카드 중 고르기'" },
    { "n": 2, "disqualified": ["D7"], "evidence": "배경 처리·부품 물성·정답 연출 중 2개가 tide-checkpoint 와 같음" },
    { "n": 3, "disqualified": [], "evidence": "붓는 양 자체가 답. 무뇌 첫 시도 정답률 12% < 우연 25%, 산출 근거 있음. 가장 닮은 tide-checkpoint 와 배경·연출 2축이 다름" }
  ],
  "predicted_fun": 16,
  "fun_mandate": ["3안 전부 실격일 때만 — 무엇을 어떻게 바꿔 반영했는지"],
  "design_mandate": ["3안 전부 D7 실격일 때만 — art_direction 을 어떻게 새로 지어 채웠는지"]
}
```

`predicted_fun` 은 이 기획이 검수에서 받을 fun 점수(20점 만점) 예측이다. **15점 미만이면 게시 못 한다고 보고**
승자 컨셉을 그 이상으로 끌어올릴 때까지 필드를 고쳐라.

## 산출물

`factory/work/chosen.json` 파일로 작성한다(네가 가진 파일 쓰기 도구를 써라). 이긴 컨셉의 내용을 **그대로 복사**하되 다음을 추가/보강한다:

```json
{
  "...선택된 컨셉의 전체 필드...",
  "_judge": {
    "scores": [{ "n": 1, "total": 84, "breakdown": { "math_is_verb": 18, "fun": 17, "curriculum": 18, "visual": 16, "feasibility": 15 }, "comment": "" }],
    "winner": 1,
    "reason": "왜 이걸 골랐는지 2문장",
    "fun_gate": [{ "n": 1, "disqualified": [], "evidence": "" }],
    "predicted_fun": 16,
    "fun_mandate": [],
    "design_mandate": [],
    "improvements": ["진 컨셉들에서 가져올 좋은 아이디어 1~3개 — 이건 승자 컨셉에 실제로 반영해서 필드를 수정해라"]
  }
}
```

**중요**: `improvements`는 적어놓기만 하면 안 된다. 승자 컨셉의 해당 필드(`core_loop`, `wow_moment`, `reward` 등)를 실제로 고쳐서 반영해라.

최종 응답으로는 `선택: <제목> (<점수>점 / fun예측 <n>) — <이유 한 줄>` 만 출력해라.
