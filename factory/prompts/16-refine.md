# 역할: 기획 보완 편집장 (3안 전부 만든다)

> 2026-10-03 사용자 지시: 「기획안을 버리지 마라. 세 개 다 만들고 싶다. 추후 사람이 감수할 것이니
> 지금부터는 기획안 중 택일이 아니라, 나온 기획안을 **보완해서 3개씩** 간다.」

`factory/work/` 의 `concept-1.json`, `concept-2.json`, `concept-3.json`(있는 것 전부)을 읽고
**하나도 버리지 말고 각각을 빌드 가능한 최선의 안으로 고쳐 쓴다.** 고르는 게 아니라 고치는 것이 일이다.

## 판정 기준 — 심사 프롬프트와 같다

`factory/prompts/15-judge.md` 를 열어 **하드 불변 5**, **채점 기준**, **fun 예측 게이트 D1~D10**,
**D7 디자인 결과 기준**을 그대로 적용해라. 다른 점은 하나뿐이다:

- 실격 사유가 걸린 안을 **탈락시키지 않는다.** 그 사유를 없애도록 **필드를 직접 고친다**
  (`core_loop`, `fun_contract`, `fail_state`, `controls`, `answer_action`, `evidence_on_screen`, `art_direction` 등).
  지시만 적고 필드를 안 고치면 무의미하다.
- `predicted_fun` 이 15 미만인 안은 15 이상이 될 때까지 고쳐라.

## 3안 사이의 차별 (이번 단계에서만 생기는 일)

세 게임이 **같은 단원으로 동시에 게시된다.** 그래서 아래를 반드시 지켜라.

1. **slug·title 이 서로 다르고**, `public/g/*/` 에 이미 있는 slug 와도 겹치지 않는다
   (`ls public/g/` 로 확인). 겹치면 새로 지어라.
2. **핵심 조작(동사)이 서로 다르다.** 두 안이 같은 동사(예: 둘 다 「각도 다이얼 돌리기」)면 한쪽을 바꿔라.
3. **디자인 시스템이 서로 다르다.** D7 의 같은 계열 판정(배경 처리·부품 물성·정답 연출 중 2개 이상 같음)을
   3안끼리도 적용해라 — 카탈로그와도, 서로와도 달라야 한다.
4. **화면으로 비교해라.** 중학교 회차면 `_school-middle.md` §7 대로 중학교 게시작 썸네일을 Read 로 열어 보고,
   「왼쪽 큰 제목 + 단일 버튼 + 빈 탁자 위 도구 하나」 틀에 빠진 안은 `art_direction` 을 다시 지어라.
   **3안 중 최소 1안은 아기자기 계열**(장난감 미니어처 디오라마 + 이 게임 전용 오리지널 캐릭터/생물이 반응)로 만들어라.
5. 한 안에만 있는 좋은 아이디어가 다른 안을 살릴 수 있으면 가져와도 된다. 단 위 1~4 를 깨지 마라.

중학교 회차면 `factory/prompts/_school-middle.md` 의 학교급 지시(2.5D 시점 기본 포함)가 본문보다 우선한다.

## 산출물

1. 각 `factory/work/concept-N.json` 을 **보완한 전체 내용으로 덮어쓴다.** 원래 필드 구조를 유지하고,
   맨 끝에 다음 블록을 추가한다:

```json
"_refine": {
  "fun_gate_before": { "disqualified": ["D3"], "evidence": "고치기 전 근거 인용" },
  "changes": ["무엇을 어떻게 고쳤는지 — 필드명과 함께"],
  "distinct_from_siblings": "다른 두 안과 동사·디자인 시스템이 어떻게 다른지 한 문장",
  "predicted_fun": 16,
  "build_order_hint": 1
}
```

`build_order_hint` 는 **먼저 만들 순서**(1~3)다 — 기대 품질이 가장 높고 구현 위험이 낮은 안을 1로 둬라.
세 안의 값이 서로 달라야 한다.

2. 최종 응답으로는 안마다 한 줄씩 `N. <제목> (<slug>) — fun예측 <n> · 순서 <k> · <주요 보완 한 줄>` 만 출력해라.
