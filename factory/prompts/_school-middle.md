# 학교급 보충 지시 — 중학교 회차 (본문과 충돌하면 이 절이 이긴다)

이번 회차는 **중학교** 게임이다(`factory/work/slot.json` 의 `school: "middle"`, `school_label`).
위 본문은 초등 공장 기준으로 쓰였다. 아래 항목은 본문의 해당 지시를 **대체**한다.

## 1. 교육과정 정본
- 교육과정 정본은 `curriculum/2022-middle-math.json` 이다(본문의 경로는 이미 이 파일로 치환돼 있다).
  성취기준 코드는 `[9수..-..]` 형식이고, 단원 id 는 `m2s2-u1` 처럼 `m` 으로 시작한다.
- `curriculum/textbook-structure.json` · `textbook-crosswalk.json` 은 **초등 교과서 전용**이다. 중학교
  회차에서는 **읽지 않는다.** 대신 `curriculum/2022-middle-math.json` 최상단의 `style_guide` ·
  `expression_traps` 와 슬롯(`slot.json`)의 같은 필드가 발문 관습의 정본이다.
  → 수학 검산관: 「textbook-structure.json 이 없으면 참조 데이터 누락 → fail」 규칙은 중학교 회차에서
  **`2022-middle-math.json` 의 `style_guide`·`expression_traps` 를 읽을 수 없을 때**로 바꿔 읽어라.
- 「5~6학년 범위를 벗어나는 수(음수, 무리수…)」 같은 초등 범위 검사는 **중학교 해당 단원 범위**로
  바꿔 읽어라. 음수·문자식은 중학교에서 정상이다. 대신 **아직 배우지 않은 내용**이 나오면 학년 부적합이다 —
  특히 **중2 에는 √(제곱근)가 없다**(중3 내용). 중2 피타고라스 문항에 √ 가 보이면 `errors` 다.
  반대로 **중3 슬롯(`m3…`)에서는 √·무리수·삼각비가 정상**이다 — 근호가 있는 답은 `a√b` 꼴(b 는 가장 작은 자연수)·분모를 유리화한 꼴로 통일한다(`expression_traps`).
  각 성취기준의 `typical_grade` 로 학년을 확인해라.
- 어림 표현 자동 검사(AT_PLACE 정규식)는 그대로 돌린다 — 무해하다.

## 2. 대상 학생과 톤
- 대상은 **중학생**(슬롯 학년)이다. 초등 저학년용 유아 톤·의성어 남발·「친구야!」식 말투는 감점이다.
- 교과서 용어(외심·내심·닮음비·빗변·사건·경우의 수 등)는 **그대로 쓴다** — 쉬운 말로 바꿔 부르면
  시험과 연결이 끊긴다. 대신 규칙 설명은 짧게, 조작으로 보여 줘라.
- 제목은 「중학생이 친구에게 링크를 보낼 때 쓰는 이름」이다. 단원명 그대로 금지는 동일.
- **고정 캐스트 「자눈 측량대」는 초등 세계관이라 중학교 게임에서는 쓰지 않는다**(`cast: null`).

## 3. 이 공장 중학교 라인의 최우선 가치 (사용자 지시 2026-09-26)
> **「첫 몇 초에 사용자를 훅 끌어당기는 디자인」과 「퀄리티 있는 게임」.**

- 기획·빌드·검수 모두 **첫 10초**를 따로 설계·평가해라: 타이틀 화면에서 무엇이 움직이고, 첫 탭에
  무엇이 터지며, 첫 정답 사건이 얼마나 손맛 있게 보이는가. 정적인 타이틀 + 설명문 벽은 실격감이다.
- 퀄리티 기준은 「교육용 치고 괜찮다」가 아니라 **스토어에 올라간 캐주얼 게임 옆에 둬도 안 밀리는가**다.
  조명·재질·카메라 연출·피드백 애니메이션·사운드가 한 세계로 묶여야 한다.
- 에셋은 필요하면 적극적으로 만든다: 이미지(`codex` 내장 이미지 생성 = gpt-image, grok 이미지),
  짧은 영상(grok video — 타이틀 배경 루프 등), 3D 모델(Blender MCP, 또는 이미지→3D). 생성물의
  프롬프트와 출처는 게임 소스 폴더에 기록한다. 상표·기존 캐릭터 복제는 여전히 금지.

## 4. meta.json 추가 필드
- `"school": "middle"` 필수(QA 가 `m…` 단원에 대해 검사한다). `grade` 는 학교급 안의 학년(중2 → `2`).
- `tech` 에는 실제 기술을 적는다(Unity 트랙이면 `["unity-webgl"]`).

## 5. Unity 트랙이면 (`meta.tech` 에 `unity-webgl`, 또는 `factory/unity-src/<slug>/` 가 있으면)
- 게임 로직·문제 생성기·정답 판정 코드는 **`factory/unity-src/<slug>/Scripts/*.cs`** 에 있다. `public/g/<slug>/index.html`
  은 공용 WebGL 템플릿 산출물이라 생성기가 없다 — 검산관·검수관은 C# 을 읽어라. 본문의
  「`public/g/<slug>/index.html` 의 문제 생성기」·`grep … index.html` 은 전부 `factory/unity-src/<slug>/` 로 바꿔 읽어라.
- `problems_sample` 은 C# `ProblemBankJson()` 이 부팅 때 푸시한 은행에서 뽑힌다. 은행이 실제 판정 경로와 같은
  생성기에서 나오는지(별도 시험지가 아닌지) 코드로 확인해라.
- 수정 에이전트는 C# 을 고친 뒤 **반드시 `bash factory/unity/build.sh <slug>` 로 다시 빌드**해야 한다 —
  소스만 고치고 빌드하지 않으면 산출물이 안 바뀌어 「무변경」으로 회차가 중단된다.
- 비주얼 판정은 QA 의 `mobile.png`·`desktop-1280.png`(실 GPU)를 기준으로 해라. 첫 플레이 프레임은 소프트웨어 렌더링
  저사양 모드라 안티에일리어싱이 꺼져 있다 — 그걸로 비주얼을 깎지 마라(`docs/unity-track.md` §6).

## 6. 사용자 비주얼 취향 — 2.5D (사용자 지시 2026-10-03)
> 「난 2.5D 느낌 좋아.」

- 기본 시점은 **2.5D** 다: 위에서 비스듬히(약 30~50°) 내려다보는 쿼터뷰·아이소메트릭 카메라(직교 투영 또는 좁은 화각),
  입체감 있는 로우폴리·디오라마 오브젝트, 바닥에 떨어지는 부드러운 그림자, 그 위의 평면 UI.
  완전 평면 2D 나 1인칭·자유 카메라 3D 보다 이쪽을 먼저 검토하고, 다른 시점을 고르면 기획서에 이유를 적어라.
- 2.5D 에서도 수학 정보(길이·각·눈금·그래프)는 왜곡 없이 읽혀야 한다 — 측정이 핵심인 장면은 직교 카메라로 정면/평면도를 잠깐 보여 줘도 된다.
