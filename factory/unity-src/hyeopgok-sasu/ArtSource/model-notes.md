# 협곡 사수 — 오리지널 3D 모델 기록

모든 게임 메시를 Blender 5.2.1 LTS의 `bpy`로 직접 만들었다. 레퍼런스의 고원·협곡·대군·석궁이라는 화면 문법만 참고했고, 이미지나 게임 에셋을 추출하지 않았다. 텍스처, 외부 라이브러리, 유료 생성 모델은 사용하지 않았다.

## 재생성

```sh
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup --python factory/unity-src/hyeopgok-sasu/ArtSource/blender/build_models.py
```

`ArtSource/blender/hyeopgok-assets.blend`와 `world-preview.png`는 검토용 원본이며 Unity로 복사되지 않는다. `.blend`의 배치와 카메라는 예시이고 게임의 실시간 전투 위치는 C#이 제어한다. Blender는 오른손 좌표계라 프리뷰 배치의 X만 반전하여 Unity 카메라와 동일한 화면 방향으로 보이게 했다. FBX에는 이 프리뷰 반전이 들어가지 않는다.

## 임포트·렌더 계약

- `Resources.Load<GameObject>("HyeopgokSasu/Models/<id>")`; 파일명은 모두 소문자.
- 단일 메시, 단일 서브메시, 플랫 노멀, 정점색. UV·텍스처·본·애니메이션 없음.
- Unity 논리 좌표: +Y 위, +Z 전방, 단위 1m. 발이 있는 모델은 원점 y=0. FBX -Z forward / Y up, baked axis conversion.
- 정점 COLOR RGB는 sRGB 팔레트. COLOR.a = 0이면 팀 색 × RGB, 1이면 RGB 고유색. 병사의 투구·몸통·방패만 팀색이다. 알파는 투명도가 아니다.
- 병사 2종 외 모델의 모든 정점은 alpha=1. 왕은 파란 망토+금관, 성문은 파란 깃발, 적 관문은 빨간 깃발.
- 모든 FBX 내 재질 이름은 `<id>_VertexPalette`. 임포터는 내장재질 생성을 생략하며 런타임의 게임 전용 정점색 셰이더를 쓴다.
- `Editor/HyeopgokModelImport.cs`가 readable, animation off, tangents off, no colliders, normals import를 설정한다. 빌드 로그에 `[HYEOPGOK RAW]`와 `[HYEOPGOK MODEL]`의 실제 Unity bounds·변환·삼각형 수를 남긴다. Unity FBX 임포트가 논리 +Z를 반사하는 것을 실화면에서 확인하여, 임포터 v2가 자식 변환을 메시로 굽고 Z 정점·노멀·탄젠트를 반사하며 삼각형 와인딩을 되돌린다. 최종 루트·자식은 모두 identity 변환이므로 공유 메시를 GPU 인스턴싱에 바로 쓸 수 있다.
- 석궁은 +Z로 발사한다. 결합 포탑 `tower` 외에 `tower_base` + localY1.62의 `crossbow`를 별도로 사용할 수 있다.
- 병영 칼 문양과 성문·적 관문 깃발은 local+Z 정면. 화면 아래쪽 카메라를 향하게 놓으려면 y축 180도 회전한다.

## 지형과 전투 정합

- 고원 평면 y=1.20, 황토 협곡 y=0.25, 외곽 녹색 띠 y=0.48, 낮은 배경 땅 y=-1.52. 절벽은 짙은 남색.
- 고원 polygon과 전투 경로 control points는 `ArtSource/blender/model-manifest.json`에 기록된다.
- 경로를 Catmull–Rom으로 연결하고 폭 ±1.02m의 황토 띠로 모델링했다. 오른쪽 위에서 남쪽으로 내려온 뒤 반원으로 돌아 왼쪽 성문 쪽으로 이어진다.
- 적 관문 2곳의 합류를 위한 황토 마당: x2.05..6.45, z6.35..11.0, y0.245. 기존 길과 겹친 곳은 길 y0.25가 위에 보인다.
- 왼쪽 수비대 접근로: x-5.5..-3.25, z-1.15..3.0, y0.245. 병영(-4.1,.25,-.30), scale.85, yaw180의 출입구가 실제 파란 부대 경로 끝 z-1에 닿는다. 성문(-4.4,.25,2.0), scale.90, yaw180은 병영 뒤쪽에 놓인다. 왼쪽 배경 절벽을 서쪽으로 옮겨 두 건물이 묻히지 않게 했다.
- 주요 오브젝트와 경로를 모델에 합쳐 굽지 않았다. 게임 로직에서 이동·출격·포탑 반동·패배 연출을 각각 제어할 수 있다.

## 검증

- Blender 헤드리스 스크립트 정상 종료. 14종 FBX 모두 생성.
- 월드 프리뷰를 직접 열어 채도 높은 초록 고원, 남색 절벽 단면, 황토 U 협곡, 두 적 관문, 청·적 부대, 석궁탑 실루엣 확인.
- 원통·지형의 와인딩을 검사·수정하여 실시간 backface culling에서 윗면이 빠지는 문제를 예방했다.
- 최종 Unity의 축/크기/셰이더 색 및 전투 위치는 메인 빌더가 WebGL 실화면에서 확인한다. 프리뷰는 게임 실행 증거를 대신하지 않는다.


## 2026-09-27 비주얼 강화 라운드

- 빨간 부대의 `soldier`는 둥근 8각 돔 투구·원형 방패(218tri), 파란 부대의 신규 `soldier_blue`는 모서리를 깎은 각진 투구·넓은 오각 방패(194tri)다. 양쪽 모두 같은 COLOR.a 팀 마스크와 인스턴싱 계약을 지킨다. 군별 두 기존 draw에 서로 다른 공유 메시를 연결한다.
- 절벽에는 불규칙 높이의 3개 암반층과 작은 턱을 만들고, 모서리의 초록 하이라이트·부분적으로 끊긴 남청 반사면을 넣었다. 차선처럼 읽히던 초기 밝은 띠를 MCP 뷰포트에서 확인하고 명도·연속성을 낮췄다. 원래 고원 polygon·도로 control points·평면 높이·왼쪽 접근로는 유지했다.
- 풀 윗면은 저대비 정점색 삼각면으로 미세한 색 변화를, 황토길은 밝은 가운데·짙은 갓길과 작은 모래 조각 220개로 질감을 냈다. 전부 terrain의 1개 메시·1개 재질로 굽는다(6,552tri). 1280 실게임 캡처에서 큰 바탕의 면이 타일처럼 읽혀, y=-1.52의 60m 배경 지면만 색 변화 진폭을 30%로 낮췄다. 주 고원의 변화는 유지했다. 텍스처·데칼·추가 프레임 할당은 없다.
- 침엽수는 3단 수관(158tri), 신규 `tree_broadleaf`는 서로 겹치는 둥근 로우폴리 수관 3덩이(242tri)다. 첫 프리뷰의 막대사탕 인상을 줄이려고 수관을 넓히고 아래로 낮췄다. 바위에는 이끼·깨진 면·작은 밑돌을 넣었다(52tri). 실제 게임의 숲 배치는 `HyeopgokWorld`가 소유한다.
- Blender MCP `get_scene_info` → `get_viewport_screenshot`으로 초기 장면, 1차 산출, 지층 수정 후, 병사 근접을 확인했다. 증거: `blender/viewport-visual-pass.png`, `blender/soldier-silhouettes.png`. `world-preview.png`는 Blender 렌더이며 실제 게임 캡처와 구별한다.
- 최종 `Blender -b --factory-startup --python .../build_models.py` 정상 완료. `--no-render`는 같은 FBX·blend를 만들되 Cycles PNG 렌더만 생략한다. Blender 5.2의 `tessellate_polygon` 인덱스 반환과 이전 Vector 반환을 모두 처리한다.
- 검수 1차 수정의 문항 압박 시간, 타이틀 입력, 온보딩, 승리 진도 HUD, 규칙·팩·브리지·봇은 이 모델 라운드에서 수정하지 않았다. 최종 Unity 화면·프레임률·폴더 용량은 통합 빌드의 별도 QA가 정본이다.
