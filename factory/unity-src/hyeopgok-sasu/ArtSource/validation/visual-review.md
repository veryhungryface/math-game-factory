# 협곡 사수 — 독립 화면 검토

검토 대상: 첫 WebGL 빌드의 `title-390.png`, `playing-390.png`, `playing-1280.png`, `correct-390.png`와 사용자 `ref/ref-1.png`, `ref/ref-2.png`를 직접 열어 비교했다. 아래는 첫 빌드의 관찰이며 수정 후 재캡처로 판정을 갱신해야 한다.

## 가장 중요한 문제

1. **P0 — 병사가 전혀 보이지 않는다.** 전투 카운터는 적 396·수비대 100 등을 표시하지만 세로·가로·정답 캡처 모두 협곡이 비어 있다. 레퍼런스의 핵심인 빨간 강물, 파란 증원, 전선 충돌과 타격감이 화면에서 사라져 있다. 포탑보다 이 문제를 먼저 해결해야 한다. 게임 오브젝트 카운트만으로는 충족되지 않는다.
2. **P0 — 지형이 논리 경로와 Z축으로 뒤집혔다.** U자 곡선이 화면 아래 대신 위에 있고, 오른쪽 길이 화면 아래에서 절단되어 있다. 아래쪽의 고원 절벽이 길게 튀어나오는 것도 같은 반전 증상이다. FBX 임포트 로그에서 병사 z bounds가 설계 `[-0.130,0.190]` 대신 `[-0.190,0.130]`임을 확인했다. 원인은 Unity의 FBX 좌표계 변환이며, 게임 로컬 임포터 v2에서 메시·노멀·와인딩을 함께 보정했다. 새 빌드 확인 필요.
3. **P1 — 팔레트와 조명이 지나치게 밝고 평평하다.** 레퍼런스는 진한 에메랄드 잔디, 남색 절벽, 뚜렷한 나무·탑 그림자와 선명한 빨강/파랑이 대비된다. 첫 빌드는 민트색 바닥·아이보리 탑 위주이며 그림자가 잘 보이지 않는다. sRGB 정점색을 Linear 셰이더 입력으로 직접 쓰는 문제를 우선 교정하고 실제 재캡처에서 광량·그림자 대비를 확인해야 한다.

## UI와 조작 가독성

- **P1 — 상단 문제 카드가 적 진입부를 가린다.** 세로 화면의 약 1/5를 차지하고 적 관문 2곳은 카드 바로 아래에 일부만 노출된다. 문제는 읽히되 전투 훅이 시작되는 위치를 가리지 않도록 카드 높이·카메라 중심을 함께 조절하면 좋다.
- **P1 — 우측 코인 숫자가 음소거 버튼과 겹친다.** `0 G` 또는 `53…` 뒤쪽을 버튼이 가린다. 실제 HUD 안전영역을 확보해야 한다.
- **P1 — 타이틀 팩 선택 줄에 □가 있다.** 지원하지 않는 펼침 문자로 보인다. 이미 제공된 글꼴 안의 문자로 교체해야 한다.
- **P2 — 분수 조판은 읽을 수 있다.** `1/2`, `1/3`를 세로 분수로 표현했고 보기 패드는 잔디 위 점선 테두리로 보인다. 정답 피드백에서도 분수 막대가 유지된다. 하단 별도 보기 버튼은 없다.
- **P2 — 왕은 금관·파란 망토로 식별된다.** 패드에 접근하는 캐릭터라는 구분은 된다. 첫 10초 안에 왕→패드→증원/포탑의 연결이 실제로 보이는지는 움직이는 전투를 복구한 뒤 확인해야 한다.
- **P2 — 데스크톱은 빈 녹색 여백이 넓다.** 현재 병사가 보이지 않아 더 심해 보인다. 떼를 복구한 뒤 전투 밀도를 다시 평가해야 하며, 단순 장식 추가만으로 해결할 문제는 아니다.

## 레퍼런스와 닮은 점·의도적으로 다른 점

- 닮은 점: 세로 중심의 높은 시점, 녹색 고원, 황토 협곡, 남색 절벽, 두 적 관문, 돌탑 석궁, 교차한 칼이 달린 병영, 금관 왕, 점선 패드.
- 다른 점: 모델과 문양은 직접 만든 오리지널이며 화면 상단에는 수학 문제, 패드에는 비용 대신 답, 하단에는 왕 이동과 0.8초 체류 안내가 있다. 사용자 제공 광고의 인물 영상·브랜드·광고 UI는 사용하지 않았다.

## 다음 캡처 판정 기준

1. 타이틀 뒤에도 눈으로 셀 수 있는 빨강/파랑 다수의 병사와 포탑 발사가 실제로 보여야 한다.
2. 오른쪽 위 관문 → 오른쪽 협곡 → 아래 U 곡선 → 왼쪽 수비대가 한 화면에서 연결되어야 한다.
3. 첫 정답 후 전선의 흰 연기·금빛 파편·날아가는 병사·석궁 효과가 빈 배경 위 텍스트와 구분되어야 한다.
4. 390 화면에서 문제 문장, 4개 답, 왕, 전선이 동시에 읽히고 HUD·음소거가 겹치지 않아야 한다.

## 세 번째 빌드 재검토 — 23:33 캡처

같은 네 장을 다시 열었다. **병사 비표시·U 경로 반전·지나친 민트색·HUD 음소거 겹침·타이틀 □는 해결되었다.** 붉은 병사 떼가 오른쪽 협곡을 가득 채우고 파란 부대가 왼쪽에서 아래 곡선으로 내려오는 구도가 보인다. 빈 첫 빌드와 달리 레퍼런스의 주된 시각적 특징이 실제 게임 안에 존재한다. 적 관문에서 별도의 두 줄이 합류하는 모습도 읽힌다.

병사 비표시는 모델 축과 별개로 인스턴싱 셰이더 변형 제거가 원인이었다. 빌드 로그에서 변형 2개가 1개로 줄어드는 증거가 확인되었고, 게임 전용 빌드 훅이 `KeepAll`을 적용한 뒤 실화면에 병사·효과가 나타났다. [Unity 6.3 공식 문서](https://docs.unity.com/en-us/engine/6000.3/manual/analysis/graphics-performance-profiling/birp/gpu-instancing-shader/strip-variants)는 씬에 인스턴싱 오브젝트가 없으면 변형이 제거된다고 명시한다. 공용 킷은 수정하지 않았다.

수정 대상으로 전달한 잔여 사항:

- **정답 설명 패널이 타격 순간의 전선을 가린다.** `correct-390.png`에서 y576~719 패널이 아래 U자 충돌부를 덮는다. 상단 문제를 잠시 정답·풀이로 교체하면 설명과 첫 정답의 손맛을 동시에 볼 수 있다.
- 전투 카운터가 y648 전선 위에 겹쳐 있다. 고원 여백이나 상단 HUD 아래가 더 적합하다.
- 성문이 왼쪽 배경 절벽에 묻혀 있다. 후속 지형 파일에서 왼쪽 절벽을 서쪽으로 물리고 황토 접근로를 추가했다. 병영(-4.1,.25,-.30), scale.85, yaw180은 출구가 실제 파란 부대 경로 끝 z-1에 맞고, 성문(-4.4,.25,2.0), scale.90, yaw180은 그 뒤쪽에 온전히 선다. 이 변경은 이후 빌드·캡처에서 확인해야 한다.
- 그림자·메시 표면의 입체감은 광고 레퍼런스보다 간결하다. 현재 화면은 실시간 저폴리 대군과 모바일 성능을 우선한 결과이며, 레퍼런스의 후처리까지 동일하다고 주장할 수는 없다.

## 후속 빌드 재검토 — 23:37 캡처

`playing-390.png`, `playing-1280.png`, `correct-390.png`를 다시 열었다. 위에서 지적한 남은 화면 배치 문제도 해결되었다.

- 왼쪽 성문과 병영이 황토 접근로 위에 온전히 서고, 파란 병사들이 병영 앞 문에서 이어진다. 절벽에 묻힌 건물이 없다.
- 정답·풀이가 상단 문제 영역을 대체한다. 아래 U자 전선, 날아가는 병사, 금빛 파편, 석궁 볼트가 가려지지 않는다.
- 전투 카운터는 화면 아래에 분리되어 전선과 겹치지 않는다.
- 가로 1280 화면은 문제와 조작 안내가 왼쪽, 전투 지형이 오른쪽에 있어 화면을 활용하며 모든 패드가 보인다.
- 이 캡처에서 새로 발견한 잘림·겹침·조작 가독성 차단 문제는 없다. 난도 규칙의 후속 소스 변경은 화면 검토의 범위를 벗어나므로 실제 마지막 빌드 캡처로 확인할 필요가 있다.

## 최종 빌드 화면 확인 — 23:42 이후 갱신본

정적 배칭·고원 나무 2개를 포함한 마지막 캡처의 `title-390.png`, `playing-390.png`, `playing-1280.png`, `correct-390.png`를 직접 열었다. **화면 잘림·UI 겹침·모델 누락으로 진행이나 전투 관찰을 막는 문제는 발견하지 못했다.**

세로 화면에는 수학 문제, 네 개 점선 답 패드, 왕, 빨강·파랑 대군, 두 석궁탑과 전선이 함께 보인다. 정답 화면은 풀이를 상단에 표시하면서 아래 충돌부의 파편·날아가는 병사·볼트를 유지한다. 가로 화면은 문제를 왼쪽에 배치하여 적 진입부와 패드를 가리지 않는다. 새 나무 두 그루도 답 숫자나 왕을 덮지 않는다. 타이틀 배경에서도 병사 떼와 사격이 보인다.

레퍼런스의 U자 협곡·밀집 대군·청적 대비·점선 건설 패드·금관 왕·석궁탑 구도는 반영되었다. 조명·표면 표현은 광고보다 단순한 저폴리 스타일이며, 그림자 품질과 타격감의 시간적 지속성은 정지 프레임만으로 정량 판정하지 않았다. 수학 검증·입력 시나리오·FPS 판정은 별도 자동 QA와 플레이 기록을 따른다.

## 최종 DPR QA 화면 확인 — 23:53 QA 산출물

위 23:42 검토는 **DPR 1 별도 캡처에 한정된 관찰**이었다. 이후 메인 빌더가 DPR 2 QA에서 초기화되지 않은 Canvas rect 너비로 인한 문제 문장 잘림을 발견하여, UI 논리 너비를 `844 * Screen.width / Screen.height`로 계산하도록 수정했다. 이 수정 후 `qa/mobile.png`, `qa/tablet.png`, `qa/desktop-1280.png`를 직접 열어 다시 확인했다. 별도 브라우저나 성능 측정은 실행하지 않았다.

- **모바일 DPR 2:** 문제 「1부터 14까지 적힌 카드 14장 … 2의 배수의 확률을 기약분수로 구하시오.」가 카드 안에 끝까지 보인다. 줄바꿈은 있으나 좌우·하단 잘림이 없고, 네 답 패드의 정수·세로 분수도 모두 읽힌다. HUD 숫자와 음소거는 분리되어 있다. 왕, 빨강·파랑 병사 떼, 석궁탑, U자 충돌부를 함께 볼 수 있다.
- **태블릿:** 같은 문제 문장이 끝까지 보이고 네 답과 왕이 가려지지 않는다. 상단 문제 카드가 적 관문의 일부를 덮고, 하단 조작 안내가 아래 U자 도로의 일부 병사를 가리는 가벼운 연출상 겹침은 남는다. 입력 대상인 왕·답 패드와 실제 청적 충돌부의 주요 부분은 보이므로 진행을 막는 문제로 판단하지 않았다.
- **데스크톱 1280:** QA가 viewport 변경으로 다시 로드한 타이틀 화면이다. 제목·팩 선택·출격 버튼·배경 전투가 모두 화면 안에 있고 잘리지 않는다. 이 한 장을 DPR 2 데스크톱 플레이 화면의 직접 증거로 삼지는 않는다. 가로 플레이 배치는 앞선 `playing-1280.png`에서 별도로 확인했다.

**최종 판정:** 최신 DPR QA 이미지에서 문제 문장 잘림은 재현되지 않았다. 새 기능적 시각 차단 문제는 발견하지 못했으며, 태블릿의 일부 장식·병사 위 안내판 겹침만 비차단 수준으로 기록한다. 실제 DPR 2 터치 동작과 FPS는 메인 빌더의 별도 실행 결과를 따른다.
