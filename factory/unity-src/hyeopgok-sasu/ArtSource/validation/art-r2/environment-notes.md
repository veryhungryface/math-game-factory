# 협곡 사수 아트 라운드 2 — 환경 구현·검증 기록

정본 요구: `../judge-r1/verdict.json`의 top_fixes 2·3·5·8과 성문 피해 HP 표시(10).
자체 점수나 상용 동급 판정은 하지 않는다. 실제 캡처 및 최종 성능 수치는 root의 최종 빌드 검증이 정본이다.

## 변경 파일과 재현

- `Scripts/HyeopgokEnvironment.cs`: 길 데칼 메쉬, 청록 접지·방향성 음영, 기단 색·크기, 성문 피해 바.
- `Scripts/HyeopgokDressing.cs`: 내부 흙길과 두 바퀴 결, 파랑 윗단 난간의 병영 마당, 횃불 2개, 소품 패드 2m 거리, 군집 숲, 저층 바위 어깨.
- `ArtSource/blender/art_r2_environment.py`: 지형만 생성하는 Blender 정본. 기존 `build_models.py`의 생성기 정의를 AST로 읽고 전체 에셋 생성 엔트리는 실행하지 않는다.
- `Resources/HyeopgokSasu/Models/terrain.fbx`: 새 지형. 다른 FBX, `model-manifest.json`, 팩 JSON/index, Rules는 이 환경 작업에서 수정하지 않았다.
- `ArtSource/blender/art-r2-environment-report.json`: 지형 단독 수출 및 실제 AO bake 수치.

재현 명령(저장소 루트):

```sh
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup \
  --python factory/unity-src/hyeopgok-sasu/ArtSource/blender/art_r2_environment.py
```

이번 수출은 실행 중인 Blender MCP에서 위 파일을 `exec(compile(...))`로 읽어 수행했다. 스크립트는 공유 Blender 장면에서 `terrain` 객체만 지우고 다시 만든다. 파일명 `terrain.fbx`와 별도 라운드 2 보고서만 출력한다. 런타임 배치는 C# 두 파일로 재현된다.

## 구현 내용

- **2 — 외부 바위**: 기존 지형에 박혀 있던 6m대 독립 암석 무리를 1.24~2.0m 높이의 연속 능선으로 교체했다. 외부 C#의 원형 대형 바위 산개 루프를 제거했다. 서쪽 상단에 0.6배 바위 어깨 3개를 추가해 긴 절벽 실루엣을 끊었다. 카메라·안개는 root의 World/Game 변경이다.
- **3 — 풀과 절벽**: 카메라에 보이는 평지 ±24m 범위를 1m 그리드로 분할했다. 고원은 가장 긴 삼각형 변 1.3m 이하로 나누었다. 공유 위치에는 같은 두 저주파 사인 합(±6%)을 RGB에 굽는다. 따뜻한 사암 윗턱 `#E9C9B0`, 절벽은 높이에 따라 `#263945`→`#838894`, Blender 기하 AO는 COLOR.a에 남긴다. 햇빛 실시간 섀도 설정·셰이더는 root 담당이다.
- **3 — 접지**: 고정 나무·건물·소품의 한 메쉬 안에 `#2C6A5A`, alpha 0.35의 페더 접지를 넣었다. 나무·탑·성문에는 실제 태양 forward의 수평 방향으로 퍼지는 alpha 0.23 로브를 더했다. 왕의 재사용 접지 반경은 0.63m로 늘렸다. 떼 그림자는 전투 담당의 고정 인스턴스 풀이다.
- **5 — 구성**: 숲은 군집당 3~9그루를 고정 난수 best-candidate 방식(후보 12개 중 기존 나무에서 가장 먼 점)으로 배치한다. 모든 정적 나무·난간·소품은 기존 CombineScenery에서 병합한다. 숲은 이 구현에서 GPU 개별 인스턴싱 대신 정적 메쉬 병합을 사용한다.
- **5 — 내부 동선**: 왕 시작점과 4개 고정 패드 중심을 잇는 흙길 loop를 만들었다. 진영 파란 상단 레일로 병영 마당을 감싸고 입구에 횃불 2개를 놓았다. 중앙 상자/통/자루/그루터기는 패드 중심 반경 2m 안에 있으면 생성하지 않는다. 작은 풀·꽃에는 별도 1.2m 가독 여백을 둔다. 길은 패드보다 아래의 평면이며 충돌·이동·판정 좌표를 변경하지 않는다.
- **8 — 층 분리**: 군대 길 바깥 둥근 녹색 띠를 안쪽 좁은 풀 어깨와 바깥 넓은 사암 턱으로 나누었다. 들여쌓기 깊이와 대각 면이 다른 절벽 조각, 일부 늘어진 풀 잎으로 외곽을 끊었다. 아래 평지는 `#208F61`~`#0D7461`로 더 차갑고 어둡다.
- **10 — 성문**: 기존 실제 성문 HP를 쓰는 피해 바의 폭·높이를 키웠다. 피해 전에는 표시하지 않는다. 탑에 가상의 HP나 피해를 만들지 않았다.

## 실제 캡처 후 2차 수정

`round1/play-390-8s.png`에서 다음 세 결함을 확인하고 수정했다.

1. 흙길의 각 짧은 선분이 자기 페더 면을 가지면서 겹침/벌어짐이 생겨 철도 침목처럼 보였다. 모든 선분이 같은 조인 행을 공유하는 `CurvedFeatheredRibbon`으로 바꾸고 닫힌 곡선의 접선도 연결했다. 폭은 0.67m, 페더 0.20m, 두 바퀴 결 alpha는 0.19로 줄였다.
2. 건물 바닥의 베이지 기단이 큰 빛무리처럼 보였다. alpha 0.65→0.20, 반경 배수 1.34→1.08로 줄였고, 작업장 바닥 alpha도 0.35→0.18로 줄였다. 실제 태양 방향의 청록 로브를 추가했다.
3. 서쪽 회색 벽의 면 분할이 시점에서 평평하게 보였다. 중간 단면 들여쌓기를 0.11~0.61m로 확대하고 두 대각 삼각형의 명도도 달리했다. 상단 암석 어깨 3개와 함께 지형을 다시 수출했다.

### 최종 미세수정

`round2-preview/play-390-3s.png`와 `play-1280-3s.png`에서 연속 흙띠를 확인했다. 다만 밝은 두 rut와 알파로 비치는 풀 때문에 금빛 링처럼 읽혔다. 최종 값은 흙 중앙 alpha **0.82**, 띠 폭 **0.58m**, 페더 **0.15m**, 밝은 두 rut alpha **0.08**이다. 새 loop 코드에서 길 색을 공유하던 두 작업장 apron도 별도 alpha **0.20**으로 분리했다. 생성 시점·개수·게임 계약은 같다.

## AO·용량 증거와 성능 범위

최종 환경 FBX: **842,588 bytes**, **14,372 triangles**, **35,154 vertices**.
실제 Blender BVHTree 코사인 반구 AO: **48 rays/corner**, **2,069,568 rays**, **626,986 hits**,
AO min **0.42**, max **1.0**, mean **0.85666**, 어두워진 corner **18,890**.
이 값은 완성 게임의 드로콜/FPS/크기 측정값이 아니라 지형 수출 계측이다.

모든 패치·길·레이아웃 난수·메쉬/리스트/재질 생성은 초기화 때만 수행한다. 경로 알파 메쉬는 별도 1회 렌더이고 나머지 정적 형상은 기존 메쉬 병합에 들어간다. 환경 LateUpdate에 새로운 배열/문자열/오브젝트 할당은 추가하지 않았다. 최종 프레임 할당은 root의 WebGL 네이티브 계측 결과로 판단한다.

`git diff --check` 및 경제 스크립트 `node --check`는 통과했다. 게임 Rules와 팩/로더를 환경 작업에서 수정하지 않았다.

## 남은 검증·한계

- round2-preview의 390/1280 실제 캡처에서 길의 침목/톱니가 사라지고 서측벽 단면이 읽힘을 확인했다. 내부 길의 밝은 링 인상과 두 작업장 apron 잔여 빛무리를 확인하여 최종 미세수정을 추가했으며, 이 최종 값은 최종 캡처에서 다시 확인해야 한다.
- 접지와 방향성 로브는 구운 페더 데칼이다. 나무 잎의 자세한 실루엣을 가진 그림자는 실시간 directional shadow에 의존한다.
- 가운데 2m 패드 여백, 고정된 군대 길, 기존 게임 지형 높이를 보존하므로 킹샷 참고처럼 모든 공간을 소품으로 채울 수 없다.
- GPU 개별 나무 인스턴싱 대신 정적 메쉬 병합을 사용한다. draw call 감소 목적은 같지만 기법은 다르다.
- 최종 390/1280 FPS·15초 유지·draw call·gzip·QA 치명 여부는 환경 단독 보고서에서 단정하지 않는다.
