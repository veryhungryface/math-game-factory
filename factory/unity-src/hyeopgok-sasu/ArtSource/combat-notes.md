# 협곡 사수 전투 구현

- `HyeopgokBattle.Init(Camera)`는 무음 타이틀 전투를 준비한다. `Begin()`은 병력·처치·성문 압박을 초기화하고 실전을 시작한다.
- API: `SetStage(int)`, `BeginQuestion()`, `Reward(int, Vector3, int hits, int trials)`, `Punish(Vector3)`, `DrainGateDamage()`, `Kills`, `Reds`, `Blues`, `Shake`.
- 오른쪽 두 관문 → 오른쪽 협곡 → 아래 U 굽이 → 왼쪽 병영의 Catmull–Rom 경로를 320점과 누적 거리로 전처리한다. 빨강 8줄·파랑 4줄의 순서 큐, 속도·간격·전선·사살/재배치 판정은 비주얼 라운드에서 변경하지 않았다.
- 기본 빨강 400 / 파랑 100, 후반 최대 빨강 598 / 파랑 150. 빨강은 `soldier`의 둥근 투구, 파랑은 `soldier_blue`의 각진 투구·방패 메시를 각각 GPU 인스턴싱한다. 파랑 리소스 로드 실패 시 기존 `soldier`로 폴백한다. 병사별 GameObject·Collider는 없다.
- 군세의 덩어리감은 렌더 행렬에서만 보강했다. 논리 위치 위에 인덱스로 결정되는 작은 좌우·앞뒤 편차와 ±3.5~4.5% 크기, ±4.5~5.5도 방향 차이를 얹고, 보폭 위상을 엇갈리게 한다. 큐/충돌 간격은 그대로이며 전투 PRNG를 소비하지 않는다.
- 기본 풀은 사체 54, 볼트 56, 기존 파편 384개다. 볼트는 발사 지점에서 길어지는 흰색 십자 단면 궤적을 남기고 포물선의 접선 방향으로 향한다. 명중·빗나감 비율과 시점은 그대로다.
- 신규 `HyeopgokImpact`는 별 섬광 20개와 흰 연기·금화·금빛 파편 합계 192개의 고정 풀이다. 평상시 0.11초 전투 틱과 실제 볼트 명중이 각각 목 지점의 섬광, 둥근 연기, 회전 금화를 만든다. 연기는 48삼각형, 금화는 32삼각형이며 풀 전체를 네 번의 인스턴스 드로로 렌더한다. 텍스처·GameObject·프레임별 배열/컬렉션 할당은 없다.
- 효과 전용 PRNG가 전투 `randomState`와 분리된다. 기존 `Burst()`와 모든 `Range()` 호출 위치·횟수는 보존해 이펙트 변경이 다음 사살·볼트 목표·병력 재배치 난수에 영향을 주지 않는다.
- 큰 처치 강조는 전투의 매 12번째 사살, 최소 0.85초 간격에서만 발생한다. 카메라 오프셋은 최대 0.085m에서 빠르게 사라지고, 45ms 동안 **이전 병사 렌더 행렬**만 유지한다. 병력 이동·사살·볼트·성문 압박·문항 시계는 계속 계산된다. `Reward()`에서 직접 화면을 흔드는 동작은 추가하지 않았다. 기존 정답 50ms 전투 일시정지는 이번 라운드에서 변경하지 않았다.
- 두 석궁 위치는 (1.75, 1.2, −3.5), (1.75, 1.2, 4.7) 그대로다. 정답의 `hits / trials` 명중 시연, 청군 충원·포탑 솟기·반동·전선 회복을 보존한다. 오답 격앙 4초·전선 밀림도 그대로다.
- f52e851 이후의 **18초 유예 → 4초마다 성문 -3**, 문항 시작 시 압박 초기화, 정답 shake 제거를 보존했다. 오래된 1차 검수의 12초/2.4초 값으로 되돌리지 않았다. 성문 HP와 종료 처리는 부모 게임이 소유한다.
- 카메라 위치는 부모만 소유하며 `Shake`를 작은 오프셋으로 읽는다. 효과음은 `Begin()` 이후에만 `MgfSfx`로 발생하고 타이틀 전투는 무음이다.

## 2026-09-27 Phase 1 — 요소·그래픽 확장

위 본문과 「비주얼 라운드 검증」은 이전 라운드의 구현·검증 이력으로 보존한다. 이번 라운드의 추가·변경 사항은 이 절을 따른다. 실제 모바일·1280 FPS·15초 유지율·드로콜·최종 게임 크기는 통합 QA 결과로 별도 기록하며 여기서 이전 수치를 재사용하지 않는다.

### 코인 운반·투입의 가시화

- `HyeopgokEconomyFx`가 지상/비행 코인 **150개**의 링버퍼와 왕 등에 보이는 최대 **20개** 스택을 유지한다. 시작·재시작 시 연출용 지갑은 **15코인**이며 실제 지갑 상한은 999다. 배열·메시·재질은 초기화 시 만들어 재사용한다.
- 처치 지점에서 코인이 튀어 오른 뒤 바닥에 눕는다. 생성 후 1.4초가 지나고 왕과의 수평 거리가 **8m 이내**면 등에 흡수되며, 거리에 상관없이 **8초가 넘으면 회수**한다. 고원과 협곡의 높이 차로 코인이 영구히 남는 일을 막는 넓은 연출용 자석이다.
- 정답 패드로 투입할 때 `min(15, wallet)`개를 0.065초 간격으로 지갑에서 빼고, 각 코인을 0.40초 포물선으로 패드에 보낸다. `HyeopgokUi`가 별도의 화면 텍스트 `건설 코인 N`을 월드 패드의 투영 위치에 붙여 남은 수를 표시한다. 문제의 보기 값 자체를 비용 숫자로 바꾸지 않는다.
- 이 지갑과 `Rules.Coins`는 별개다. 운반 코인은 **연출·재화 표시**이고 정답 판정·건설 보상 지급 여부·성문 HP·웨이브·승패에는 관여하지 않는다. 패드에서 0.8초 정지해 답을 선택하는 조작과 팩의 문항/보기 구조는 유지한다. 실제 코인 수를 계산해 채워 넣는 수학 경제는 후속 단계 범위다.

### 유닛·전투 효과

- 적 기본병·궁수·거인·보스는 같은 기존 이동 큐의 **시각 종류**다. 인덱스 기반 `KindFor()`로 궁수와 거인을 섞고, 10번째 웨이브 진입 시 `redKinds[120]`을 보스로 바꾼다. 종류는 큐 이동을 따라가며 독립 공격력·공격 판정·체력을 추가하지 않는다. 석궁탑 위 아군 궁수 2명도 기존 사격의 시각 표현이다.
- 거인·보스 머리 위 빨간 막대는 `clamp01((front - redS[i]) * 0.24 + 0.13)`으로 줄어드는 **전선 거리 기반 표시**다. 독립 개체 HP를 시뮬레이션한 결과가 아니며, 거인이나 보스의 실제 생존력이 늘었다고 해석하면 안 된다. 빛나는 무기는 추가 인스턴스 행렬로 표현한다.
- 공격 때 앞으로 기울기, 아군 흰 스폰, 사망 흰 실루엣을 기존 행렬 렌더에 추가했다. 사체의 난수·물리는 계속 계산하되 시각 사체는 220ms 이후 숨긴다. 기존 처치·재배치·명중 시연·성문 압박을 보존한다.
- `HyeopgokImpact`는 기존 192개 입자·20개 섬광 풀에 주황 불꽃·어두운 연기·건물 화재를 더하고, 숫자 팝업 20개 풀을 쓴다. 피해 숫자는 초기화 때 만든 7세그먼트 메시로 그린다. 팝업마다 텍스트 오브젝트나 폰트 아틀라스를 만들지 않는다.

### 건물·환경·색

- 석궁탑·병영·성문은 3단계 FBX를 부팅 때 준비해 성장 시 활성 메시를 바꾼다. 목재→석재와 파란 천→성가퀴/슬레이트로 외형이 커지고, 건설 중 `_Flash`와 `_Unlit`을 이용한 흰 실루엣·상승 연출을 보여 준다. 독립 건설 타이머나 추가 수학 조건은 없다.
- 목책 3구간은 기존 성문 HP 100을 각각 약 33.333씩 나누어 표시한다. `clamp01((environmentHp - i * 33.333) / 33.333)` 값에 따라 정상/손상 메시/소멸, 막대와 화재를 바꾼다. 구간별 별도 피해 계산이나 새로운 공성 규칙을 추가하지 않는다.
- 분홍 적 마당·붉은 지붕 관문 2채·망루, 풀 다발·꽃·자갈·저대비 얼룩·접지 그림자, 사암/숲 가장자리, 물과 다리, 밤 전환을 더했다. 기존 경로·고원 답 패드 좌표는 유지한다. 다리는 열어 둔 지형 구간을 덮는 시각 병목이다.
- Blender sRGB 정점 팔레트와 Unity Linear 렌더링의 관계를 맞췄다. 전투의 빨강 `#d0060c`, 파랑 `#0c6fd3` 팀 재질은 `Color.linear`로 변환해 셰이더에 전달한다. 발광 효과의 색·밝기는 별도로 조절하며 모든 재질에 무조건 이중 변환하지 않는다.

### 풀·난수와 문항 제한 시간

- 새 코인·효과 난수는 전투 난수와 분리한다. 종류 선택·모델 스왑·공격 기울기는 전투 PRNG를 소비하지 않으며, 기존 시뮬레이션의 `Range()` 소비·병력 간격·경로·처치/볼트 목표 계산은 유지한다. 신규 인스턴싱 행렬과 HP/코인/효과 배열은 크기가 고정되어 있고 프레임마다 메시·재질·배열을 생성하지 않는다.
- 검수 잔여 지적에 따라 **문항 제한 시간은 규칙 변경**했다. 팩의 기존 `difficulty` 값이 1 이하이면 24초, 2이면 32초, 3 이상이면 40초다. 두 주사위 등 계산량이 큰 문항에 시간을 더 주며 팩 JSON을 재작성하지 않는다. UI에 `24/32/40초가 지나면 오답`과 남은 시간을 명시한다. 성문 압박은 기존 18초 유예 뒤 4초마다 -3을 유지하고, 24초 기준의 빠른 정답 보너스도 그대로다.
- 제한 시간 변경 후 루트가 봇을 재실행했다. 제한 직전/직후의 판정 경계와 팩별 정답 대조군·첫 오답 회복 검사는 통과했고 **모델 단위 검증 오류는 0건**이었다. 다만 일부 무뇌 봇의 유한 표본 정답률이 25%를 넘어, **모든 원시 관측값 ≤25%라는 문자 그대로의 조건은 미충족**이다. 대칭 검사와 기대값의 우연 수준을 이 원시 조건의 통과로 대신하지 않는다. 상세 수치·해석·한계는 `ArtSource/bot-results.md`와 `ArtSource/validation/bot-results.json`을 따른다.
