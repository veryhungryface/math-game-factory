# 협곡 사수 전투 구현

- `HyeopgokBattle.Init(Camera)`는 화면 뒤에서 즉시 도는 타이틀 전투를 준비한다. `Begin()`은 병력·처치·성문 압박을 초기화하고 실전을 시작한다.
- API: `SetStage(int)`, `Reward(int, Vector3)`, `Punish(Vector3)`, `DrainGateDamage()`, `Kills`, `Reds`, `Blues`, `Shake`.
- 오른쪽 두 적 관문 → 오른쪽 협곡 → 아래 U자 굽이 → 왼쪽 병영으로 이어지는 Catmull-Rom 경로를 320개 점과 누적 거리로 전처리한다. 8줄 빨간 병사와 4줄 파란 병사가 앞 병사의 거리보다 가까이 갈 수 없는 순서 큐로 분리된다.
- 기본 빨강 400 / 파랑 100, 후반 최대 빨강 598 / 파랑 150. 병사는 원본 Blender FBX를 정점색 마스크 기반 사용자 셰이더로 GPU 인스턴싱한다. 직접 만든 접지 그림자는 별도 인스턴스다. 병사별 GameObject·물리 충돌기는 없다.
- 전투는 부딪히는 앞줄, 54개 고정 쓰러짐 풀, 56개 볼트 풀, 384개 금빛/흰색/흙빛 파편 풀을 사용한다. 프레임당 Instantiate·컬렉션 확장·문자열 조립 없음.
- 두 석궁 포탑은 (1.75, 1.2, −3.5), (1.75, 1.2, 4.7)에 놓인다. 정답이면 올라오기·압축 반동·20발 연속 사격·전선 밀어내기·청군 충원, 50ms 전투 히트스톱이 발생한다. UI/왕 입력의 시간을 멈추지는 않는다.
- 카메라 위치는 부모만 소유한다. `Shake`를 읽어 작은 오프셋을 적용해야 한다. 정답 전투 충격도 사용자의 레퍼런스 요구에 따라 짧게 흔든다.
- 오답은 4초 적 격앙과 전선 밀림. 무응답 12초 후 2.4초마다 `DrainGateDamage()`에 3점을 쌓으며, 성문 HP와 종료 처리는 부모가 한다. 정답/오답 모두 새 문항의 압박 시간을 초기화한다. HP100·오답18 구조에서 15초 정답을10번 풀거나 첫오답 후9번 정답을 풀어도 살아남는다.
- 경로 제어점은 Blender 지형의 `PATH_POINTS`와 정확히 일치한다. 셰이더는 Built-in ForwardBase 그림자 수신과 인스턴스 ShadowCaster를 지원하며, 병사만 실제 그림자를 끄고 가벼운 접지 그림자를 사용한다.
- `MgfSfx` 전투 효과음은 `Begin()` 이후에만 호출한다. 타이틀 데모는 무음이다.

검증 상태: 소스 구현 완료. Unity 컴파일·실기 FPS·시각 QA는 루트 에이전트의 단일 빌드/하네스 실행에서 검증한다.
