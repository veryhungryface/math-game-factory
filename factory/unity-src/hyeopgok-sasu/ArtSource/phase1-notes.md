# 협곡 사수 v2 — 비주얼·요소 1단계

2026-09-27. 사용자 지정 범위는 비주얼·요소 개선이다. 코인으로 수학 답을 구성하는 2단계는 구현하지 않았다. 왕 이동 → 보기 패드 0.8초 정지 → 기존 정답 판정을 유지한다. 공개 메타는 version 2 / 미심사로 리셋했으며 push·게시·배포하지 않는다.

## 제한 시간 잔여 지적

팩 스키마·문항·정답·승패 조건은 그대로다. 기존 `difficulty`만 읽어 난도 1은 24초, 2는 32초, 3 이상은 40초로 변경했다. 경우의 수의 두 주사위는 난도 2, 확률의 두 주사위는 난도 3이어서 각각 32초·40초를 받는다. 문제 아래 `○초가 지나면 오답`·남은 시간·성문 압박을 명시한다. 시간초과 피드백에도 `시간 초과 · 오답 · 성문 -18`을 표시한다. 기존 18초 유예/4초마다 -3 압박과 24초 기준 빠른 답 보너스는 변경하지 않았다.

전 팩 844문항의 제한 직전/직후 경계 검사와 기존 production `Move`/`Tick` 봇을 재실행했다. 모델 오류 0, 정답/첫 오답 회복 대조군 통과, 대칭 정답률 정확히 25%. 원시 무뇌 봇 일부는 25%를 초과한다(최대 26.95%); 기준 시드·표본 수를 바꾸거나 통과로 덮어쓰지 않았다. 정본은 `bot-results.md`와 `validation/bot-results.json`이다. `validation/phase1/bot-results-before.*`에 이전 기록도 보존했다.

## 직접 본 화면과 수정

- `validation/phase1/before/`: 시작 빌드의 실제 WebGL. 390/1280 드로콜 최대 170/227로 이미 150을 초과했다.
- `round1/`: 새 모델·연출 통합. 맵의 개별 점선 64개를 한 메시로, 정적 세계를 재질/그림자 조건별 메시로 합쳐 최대 140으로 줄었다.
- 킹샷 2프레임 + 실제 전투 2프레임의 `compare.png`를 직접 열어 비교했다. 가로 전선 하단 잘림, 겹쳐 보이는 관문 지붕, 중복 코인 숫자, 긴 문항 높이를 찾아 수정했다.
- `final/`: 가로 카메라 12% 추가 후퇴·관문 스케일 .93·단일 코인 카운트다운·실제 텍스트 높이에 따른 글자 크기 조절·팀 색 보정·독자 흰 투구 플레이어를 재캡처했다.
- 2차 캡처에서 정답 분수 팝업의 자식 분수가 다음 문항에도 남는 기존 버그를 발견했다. 팝업의 분수 자식까지 정리하고, 모바일 코인 HUD는 빈 왼쪽 공간으로 옮겨 관문 가림도 없앴다. 재시작 시 드래그 잔여 상태도 초기화했다. `round2/`는 이 수정 전 증거, `final/`은 3차 빌드 증거다.

## 재현·증거

```sh
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup --python factory/unity-src/hyeopgok-sasu/ArtSource/blender/build_models.py
bash factory/unity/build.sh hyeopgok-sasu
node factory/unity-src/hyeopgok-sasu/ArtSource/validation/phase1/capture.mjs final
python3 factory/unity-src/hyeopgok-sasu/ArtSource/validation/phase1/make_artifacts.py --tag final --install-public
node factory/unity-src/hyeopgok-sasu/ArtSource/validation/phase1/integration.mjs
node factory/lib/qa.mjs hyeopgok-sasu --out factory/unity-src/hyeopgok-sasu/ArtSource/validation/phase1/qa
```

Blender MCP와 헤드리스 생성으로 같은 35종 FBX를 확인했다. 메시 raw 990,804 bytes / 개별 gzip 합 568,906 bytes, 새 텍스처 0 bytes. 실제 WebGL API의 draw 호출(그림자·UI 포함)을 재며, 캡처용 계측은 게임 코드에 들어가지 않는다. 최종 QA·크기·해시·빌드 증거는 `validation/phase1/summary.json`에 기록한다. 표지는 실제 네이티브 크기 캡처에 제목 띠만 더하며, 참고 이미지의 픽셀은 공개 표지에 쓰지 않는다.

실 GPU Chrome/Apple M4 측정은 실제 iPhone의 발열 검증을 대신하지 않는다. 킹샷보다 표면 질감·조명·독립 유닛 AI/공성 상호작용이 간결하며, 수학 경제 루프는 다음 단계다.

## 드로콜 경계 스트레스 검증

일반 5판형·성장·밤·보스 캡처에서는 최대 129 호출을 관측했다. 추가 화재/패배/재시작 검사에서 별도 rAF 표본 최대 226/232가 잡혀 측정 경계를 추적했다. Unity의 `Module.preMainLoop/postMainLoop`로 엔진 루프 한 번을 직접 감싸고 RAF 밖 동기 렌더 작업도 별도 집계했다. 화재·종료·재시작의 엔진 루프 최대는 모바일 119/1280폭 123, 루프 밖 작업 최대는 113/116이다. 모든 GL draw 합계가 RAF 콜백 안/밖 합계와 일치하며 누락은 0이다. 종료와 재시작 때 추가 동기 렌더가 기존 rAF 표본과 합산된 것이므로 226/232는 한 Unity 렌더의 드로콜이 아니다. 원시 표본·pass clear 흔적도 `edgecases.json`에 보존했다. `clear` 사이 값은 렌더 패스별 값이므로 단독 게이트 근거로 사용하지 않았다.

최종 빌드에서 네 오답 뒤 HP 28·손상 목책·화재를 캡처하고, 드래그를 유지한 채 패배→재시작 후 HP 100·왕의 목표 위치 초기화를 확인했다. 390/1280 모두 브라우저 오류 0. 긴 실제 터치 통합 검증은 2차 빌드 증거이며, 이후 바뀐 것은 분수 팝업 정리·모바일 코인 HUD 위치·재시작 드래그 초기화뿐이다. 그 수정은 3차 `final/` 캡처·이 경계 검사·최종 공식 QA에서 확인했다.
