## 재생성과 검증

```bash
cd factory/unity-src/hyeopgok-sasu/ArtSource/packs
for u in 1 2 3 4 5 6; do node gen-m2s1-u$u.mjs; done   # 결정적(재실행 시 해시가 같다)
```

## 독립 검산 (check-m2s1.mjs) — 결과: 6팩 2,293문항 전부 pass, 실패 0

검산기는 문항의 `params`와 **학생이 보는 발문 문자열 자체**를 다시 읽는다. 자체 수식 파서(분수 토큰·`<sup>`·²·³·암묵적 곱 처리)와 BigInt 유리수로 계산하며, 생성기와 다른 방법을 쓴다.

| 단원 | 생성기 방식 | 검산기 방식 |
|---|---|---|
| u1 | 긴 나눗셈으로 순환마디 추출 | 순환마디 길이 = 10의 곱셈적 위수, 비순환 길이 = 2·5 지수, n번째 자리 = ⌊p·10ⁿ/q⌋ mod 10, 소수→분수는 **표시된 숫자열**에서 (N−M)/(10ˢ(10ᴸ−1)), 유한소수 판정은 긴 나눗셈 종료 여부, 표시 숫자열과 p/q의 모든 자리 대조 |
| u2 | 기호 다항식 연산 | □에 0~70을 넣어 좌변≡우변을 6개 유리수 점에서 평가, **해가 정확히 하나**인지 확인. 자릿수는 BigInt 전개 |
| u3 | 부등식 기호 풀이 | 정수 −3000~3000 전수 탐색, 경계는 선형 탐침 ±1/1000으로 포함/제외 판정, 활용은 자연수 전수 열거 |
| u4 | 해에서 역산해 계수 구성 | 두 식에 정수 격자 −80~80 전수 대입 + 행렬식≠0, 계수 a·b는 −60~60 전수 탐색, 활용은 전수 열거 |
| u5 | 기울기·절편 공식 | 표시된 식을 평가(탐침), 양초·물통·기온·용수철은 1분/100 m 단위 시뮬레이션, 함수 판별은 관계를 x=1~30에서 y값 집합으로 재구현, 사분면은 x를 1/8 간격으로 표본 |
| u6 | 계수 비례식 | 계수 탐침, 해 개수는 격자 공통점 수 + 비례 판정, 넓이는 격자 칸 세기·유리수 공식 |

추가로 매 문항을 확인한다: 구조(validate-pack), 성취기준이 해당 단원에 실재, answerNumeric, 함정 값≠정답, choice 보기 4개 서로 다름·정답 유일, 분수 입력 431,636쌍의 런타임 수용 규칙과 오라클 일치, √·폰트에 없는 글리프·평문 분수·`{frac:n/1}` 금지, TMP 마크업 위험 문자열 금지.

## 설계상 선택

### 음수 답 처리 (코인은 0 이상 정수만)
- **붓기 문항은 양수가 되도록 묻는 대상을 고른다.** 음수는 식 안에는 자유롭게 나온다(−5x+9≤−2x−8, y=−2x+6, 계수 −3a 등).
  - u3: 해 x>−30 자체를 붓게 하지 않고 「만족하는 음의 정수 x의 개수」「가장 작은 자연수」「가장 큰 정수(양수일 때)」로 묻는다.
  - u4: 해를 정수 해에서 역산해 x, y, a+b가 자연수가 되게 했다.
  - u5·u6: 음의 기울기가 아닌 양의 x절편·증가량·넓이를 묻는다(y=−2x+6의 x절편 3).
- **부호 자체가 학습 목표인 것은 choice로 뺐다:** 부등식 해(x>−3 / x<−3 / x>3 / x≥−3), 수직선 ●/○·방향, 음의 기울기(−{frac:12/7} 대 역수·부호 오답), 음의 x절편, (−2a)³ 같은 음수 밑의 거듭제곱, 평행이동한 식, 사분면, y축/x축에 평행한 직선, 해의 개수↔평행·일치. choice 비율은 10~24%로 30% 이하다.
- 억지로 양수로 바꾸지 않았다: 양수 조건을 거는 대신 음수가 자연스러운 문항은 다른 물음(개수·넓이·절편)으로 바꾸거나 choice로 보냈다.

### 분수 답
- u1 순환소수→분수 70문항: 발문에 「기약분수로 나타내시오」 → `reduced`.
- u5·u6 기울기·x절편 46문항: 발문이 기약분수를 요구하지 않으므로 `equivalent`(4/6과 2/3 모두 정답). 라벨은 「분모」「분자」.
- `exact_parts`는 쓰지 않았다(review-v2-2 교훈: 세는 방법이 발문에 고정되지 않으면 옳은 풀이를 오답 처리한다).

### 표기 (게임 폰트 제약)
- 폰트(MgfKR 서브셋)에 ⁴~⁹와 결합 점(U+0307)이 없다. **지수는 TMP 태그 `<sup>n</sup>`**(두 폰트 모두 위첨자 지표 350/600 보유), **순환소수는 점 표기 대신 펼친 숫자 + 「…」**(0.2454545…, 짧은 순환마디는 3회 이상 표시)로 썼다. 점 표기 자체를 묻는 문항은 없다.
- UI 본문 폰트가 Jua로 바뀌었지만 Jua에 없는 −·×·≤·□·①·ㄱ 등은 MgfKR 폴백으로 그려진다. 6팩에 쓰인 모든 글자가 MgfKR에 있다(누락 0).
- `a<b일 때`처럼 TMP가 태그로 읽을 수 있는 `<`+영문자+공백/`=`/`>` 모양이 없도록 생성기와 검산기가 모두 검사한다.
- 교과서체 「~을 구하시오」「□ 안에 알맞은 수를 구하시오」「~을 고르시오」「~을 푸시오」, 조사(을/를·이/가·은/는·과/와·으로/로)는 숫자·문자·분수·지수 뒤의 발음으로 골랐고 전체 스캔에서 불일치 0건이다.

### 식의 계산(u2)
기호 답을 부을 수 없으므로 교과서의 「□ 안에 알맞은 수」 형식을 쓴다. 학생은 결과 전체를 계산해야 □의 계수·지수를 알 수 있다. 지수는 자연수만, (다항식)÷(단항식)은 몫이 다항식인 경우만(교육과정 해설).

### 고유 문항과 validate-pack의 괄호 규칙
validate-pack은 `(...)`를 지우고 중복을 판정한다. 그래서 괄호 안만 다른 문항(예: `(4a³b−18a²b²)÷2a`)이 한 문항으로 합쳐지는 문제가 있어서 (1) 나눗셈은 「…을 2a로 나누면 …이다」로, 점은 필요한 곳에서 「x좌표가 3이고 y좌표가 −1인 점」으로 바꾸고 (2) 중복 키가 겹칠 때 남는 대표를 무작위로 골라 파라미터가 한쪽으로 쏠리지 않게 했다.

### 교육과정 범위
연립일차부등식(2015 개정 이후 고1)은 넣지 않았다. 순환소수는 9가 반복되는 표현이 생길 수 없게(긴 나눗셈에서 생성) 했고, 순환마디 1~3자리·비순환 0~2자리로 제한했다. 활용 문항은 요금제·단체 입장·등산·양초·물통 등 교과서형 단순 상황만 썼다.

## 남은 위험

1. **분수 모드 힌트 문구가 확률 전용이다.** `HyeopgokUi.cs`의 fraction_parts 힌트가 「모든 경우 → 사건의 경우 순서로 붓기」로 하드코딩되어 있다. m2s1의 분수 116문항은 라벨이 「분모」「분자」라서 힌트와 맞지 않는다. 힌트를 den_label/num_label 기반으로 바꾸는 Unity 수정이 필요하다(팩으로는 해결할 수 없다).
2. **`verify-packs.mjs`는 m2s2 전용이다.** index.json을 순회하면서 `semester===2`, `*-proofs.json`, m2s2 유형만 인정한다. m2s1 팩을 index에 넣으면 그 스크립트가 실패하므로 m2s1은 `check-m2s1.mjs`로 검산해야 한다(또는 verify-packs가 m2s1을 건너뛰게 해야 한다).
3. **긴 choice 라벨:** 일부 보기가 7~12자다(「일치, 해 무수히 많음」, 「분수로 나타낼 수 없다」, 「−20에 ●, 왼쪽」). 패드 글꼴은 6자부터 13px로 줄어든다. 실제 WebGL 패드에서 줄바꿈과 가독성을 확인해야 한다.
4. **긴 발문:** 목록형(함수 판별 5개 진술, 일차함수 식 6개)은 최대 191자다. 문제 패널이 높이를 늘리지만 390×844에서 전장을 얼마나 가리는지 실기 확인이 필요하다.
5. **`<sup>` 렌더링은 실기로 확인하지 않았다.** 폰트 지표로는 문제가 없지만 WebGL 빌드에서 지수 위치를 한 번 봐야 한다. 기존 m2s2 팩은 `<sup>`을 쓰지 않는다.
6. 큰 붓기 답(40~59닢)은 전투 중 코인 수급 시간이 더 든다. 경제 계약(≤60)은 지키지만 체감 난이도는 봇·실기 검증이 필요하다.
